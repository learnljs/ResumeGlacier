# refactor — 重构约束与执行流程

本 Skill 约束**重构阶段**的所有代码改动（代码结构重构、代码质量提升、UI 重设计）。与 `CLAUDE.md` 编码准则冲突时，以本 Skill 为准——本 Skill 更严格。

## 一、核心原则

1. **行为不变**：重构不改变任何外部行为——API 请求/响应、状态流转、UI 展示、数据库写入、日志格式、定时任务行为。任何行为变化必须在报告中显式声明。
2. **一次一个模块**：一个任务只重构一个模块（`lib/services/`、`app/api/` 下的一组路由、`components/` 下一组组件、`app/resume/` 下一个子域）。绝不跨模块改动。
3. **结构优先于重写**：优先 move / extract / inline / 合并；确需重写时，逐函数对照原逻辑，禁止凭印象重写。
4. **先计划后动手**：动手前先输出重构计划（文件清单、改动顺序、风险点、验证方式），等待人类确认后再执行。
5. **每步可验证**：每个模块完成即验证，不留到收尾统一验证。

## 二、禁止事项（重构期间）

- ❌ 不顺手修改无关代码：不格式化、不重命名、不"优化"目标模块之外的代码；发现的无关问题记入 backlog，不在本次处理
- ❌ 不新增 npm 依赖（除非计划中显式声明并说明理由）
- ❌ 不做投机性抽象：接口 / 泛型 / 工具函数必须服务 ≥2 个真实调用点，否则保持内联
- ❌ 不改动外部契约：API 路径与字段名、数据库字段名、环境变量名、队列任务类型、定时任务签名
- ❌ 不把确定性逻辑交给模型：重试策略、路由逻辑、阈值判断、硬条件筛选、规则打标必须写成显式代码（参考 `lib/services/hard-condition-filter.ts`、`lib/services/tag-detector.ts`）
- ❌ 不引入新的模块级可变状态；Prisma 客户端与后台队列保持 `globalThis` 单例
- ❌ 不混合两种矛盾模式：发现代码库存在冲突时，先报告并询问遵循哪个，不自行选择、不折中

## 三、兼容性红线

- **SQLite 三大约束**：不支持并发写（队列并发=1、单进程运行）；无 ALTER COLUMN（改字段需重建表）；无迁移（直接 `prisma db push`）。schema 任何改动必须在计划中显式声明重建表步骤。
- **加密数据**：`ENCRYPTION_KEY` 相关字段（邮箱密码、AI API Key、Webhook URL）的存储格式与解密逻辑不得在重构中顺手改写，除非是专门任务。
- **废弃字段**：`Resume.initialScore` / `compositeScore` / `screenedDate` 不得重新启用；相关读取必须走 `PositionEvaluation`。
- **不降级类型安全**：重构后 `npx tsc --noEmit` 必须零错误；禁止用 `any` 规避类型问题。

## 四、代码生成约束

生成新代码 / 改写代码时必须满足：

1. **命名**：`lib/services/` 下 kebab-case，React 组件 **PascalCase**（2026-08-25 决策 D1 已统一，B10 将批量重命名存量 kebab-case 文件），API RESTful 风格
2. **导入**：一律使用 `@/*` 路径别名
3. **样式**：用 `cn()`（`lib/utils.ts`）合并 className；颜色、圆角、阴影等设计令牌必须在 `app/globals.css` 的 `:root` 中定义后引用，禁止硬编码色值
4. **类型先行**：涉及跨文件改动的重构，先更新类型定义再改实现，保证全程可编译
5. **语言**：UI 文本、注释用中文，技术术语保留英文
6. **复杂度门禁**：函数超过 60 行或嵌套超过 3 层必须拆解；重复代码抽成服务/工具函数而非复制粘贴
7. **错误处理**：保持现有错误处理风格（中文错误信息），不吞异常；空 catch 必须处理或明确注释原因

## 五、执行流程

1. **读文档**：先读 `CLAUDE.md`、`REVIEW.md`、`CONTRIBUTING.md`、`docs/refactor-audit.md`（现状盘点报告，含已裁决决策），确认架构、规范与已知问题
2. **冻结基线**：记录当前 `npm run lint`、`npx tsc --noEmit`、`npm run build` 结果；涉及数据库重构先备份 `prisma/data/resume.db`
3. **出计划**：输出重构计划（见 `docs/refactor-prompts.md` 模板 P1），等确认
4. **逐模块重构**：每完成一个模块，跑：

   ```bash
   npm run lint && npx tsc --noEmit && npm run build
   ```

   并通过 Playwright MCP 对关键路径冒烟（列表页、详情页、操作流）
5. **分步提交**：每模块一个 `refactor:` commit，commit message 写清改动范围与行为是否变化
6. **报告**：任务结束报告「改了哪些文件 / 验证结果 / 是否有行为变化」，等待确认再进入下一模块

## 六、提示词模板

完整模板库见 `docs/refactor-prompts.md`（P0 现状盘点 / P1 重构计划 / P2 单模块重构 / P3 行为对照审查 / P4 质量提升 / P5 UI 重设计 / P6 整体审查 / P7 个人化清理）。快速开始：

> 重构 `lib/services/xxx.ts`：行为不变，只做结构优化。先给计划，确认后动手，完成后跑 lint/tsc/build 并报告 diff 摘要。
