> 新环境直接 `npm run db:setup`（`prisma db push`）即可，**无需执行本变更脚本**；
> 本文档与 `deploy/script/prod/001-add-contacted-field.sql` 作为该次线上变更的留档。

> **目标环境**: 正式环境，环境配置见 [`deploy/env/prod.md`](../../env/prod.md)

## 变更概述

- **关联 Spec**: [`docs/dev/跟进管理模块/联系结果登记功能_task-39b.md`](../../../docs/dev/跟进管理模块/联系结果登记功能_task-39b.md)
- **变更类型**: 表结构变更（新增字段）
- **变更日期**: 2026-07-07
- **目标表**: `FollowUpRecord`

## 变更内容

### 新增字段

| 表名 | 字段名 | 类型 | 默认值 | 是否必填 | 说明 |
|------|--------|------|--------|----------|------|
| FollowUpRecord | contacted | TEXT | 'NOT_CONTACTED' | 是 | 联系结果状态 |

### 字段枚举值

| 值 | 中文标签 | 含义 |
|----|----------|------|
| NOT_CONTACTED | 未尝试 | 刚进入沟通中，尚未尝试联系（默认值） |
| CONTACTED | 已联系上 | 已成功触达候选人 |
| CONTACT_FAILED | 未联系上 | 尝试过但未成功触达 |

## 影响范围

### 上游依赖
- `prisma/schema.prisma` - Prisma Schema 已更新
- Prisma Client 需重新生成（`npx prisma generate`）

### 下游影响
| 组件 | 影响 | 说明 |
|------|------|------|
| `GET /api/follow-up/records` | 新增筛选参数 | 支持 `?contacted=` 查询参数 |
| `PATCH /api/follow-up/records/[id]` | 新增更新字段 | 支持单独更新 `contacted` |
| `POST /api/follow-up/export` | 新增导出字段 | 导出时包含联系结果列 |
| 前端跟进管理页 | 新增 UI 列 | 沟通中 Tab 显示联系结果下拉 |

### 不受影响
- 现有数据的 `contacted` 字段将自动填充默认值 `NOT_CONTACTED`
- 非沟通中 Tab（待面试/已面试/已录用/不合适）不展示该字段
- 现有 API 调用不传 `contacted` 参数时行为不变

## 数据库迁移

> 代码部署步骤（拉取代码、安装依赖、构建、启动）参见 [`deploy/env/prod.md`](../../env/prod.md)。
> 部署前务必先备份数据库。

执行 SQL 迁移脚本：

```bash
# 正式环境推荐执行 SQL 脚本
sqlite3 prisma/data/resume.db < deploy/script/prod/001-add-contacted-field.sql
```

### 验证

```bash
# 验证字段已添加
sqlite3 prisma/data/resume.db ".schema FollowUpRecord" | grep contacted
# 预期输出：contacted TEXT NOT NULL DEFAULT 'NOT_CONTACTED'

# 验证现有数据默认值
sqlite3 prisma/data/resume.db "SELECT id, contacted FROM FollowUpRecord LIMIT 5"
# 预期：所有现有记录 contacted = 'NOT_CONTACTED'
```

## 回滚方案

> SQLite 不支持 `ALTER TABLE DROP COLUMN`。简单回滚方式为回退代码后重新 `npx prisma db push`，Prisma 会检测差异并通过重建表方式移除字段。如字段影响较小，建议保留。
