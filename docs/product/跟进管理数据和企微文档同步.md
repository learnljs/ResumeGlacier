# 跟进管理数据同步至企微智能表格

## 一、需求背景

当前 HR 系统中的跟进管理数据（候选人、面试过程、面试结果）全部沉淀在系统内部，团队以外的角色（老板、业务部门负责人、其他协同同事）想了解招聘进度，目前只能由 HR 手动复制、截图或口述同步，效率低且容易出现信息滞后、信息不一致。

企业微信「智能表格」提供了「接收外部数据」开放能力（[官方文档](https://developer.work.weixin.qq.com/document/path/101239)），允许外部系统通过 Webhook 协议将数据写入到一份指定的智能表格。我们希望复用这个能力，让 HR 系统在跟进管理出现关键节点变化时，自动把数据同步到企微端的智能表格，让协作者在企微端就能实时看到与 HR 系统基本一致的招聘进展。

## 二、为什么需要做这个改动

1. **信息同步效率低**：业务方、老板想了解招聘进度，每次都得找 HR 问，HR 又得手动整理，重复劳动。
2. **数据容易不一致**：人工同步过程中，口径和时效都没保障，看到的可能已经是过时版本。
3. **企微已经是日常工作平台**：大家日常在企微沟通，把数据落到企微智能表格里，零学习成本，无需额外打开系统。
4. **现有能力已经具备**：企微智能表格开放了 Webhook 接入能力，无需额外的 UI 二次开发即可打通。

## 三、需求目标

**核心目标**：在 HR 系统内部跟进管理出现关键节点变化时，自动把对应数据推送到企微智能表格，让协作者在企微端就能看到与 HR 系统基本一致的信息。

**典型场景**：

- HR 在「沟通中」子页面点击「预约面试」后，候选人进入「待面试」列表 → 同步一条新记录到企微表格。
- 候选人面试完成（HR 在「待面试」点击「面试结束」进入「已面试」）后 → 同步更新面试状态、面试评价等到企微表格对应记录。
- 候选人后续状态变化（录用、拒绝 / 不合适、待入职、离职等）→ 同步更新企微表格对应记录。

## 四、我们要同步什么内容

> **重要前提**：企微智能表格的字段定义、字段 ID、字段类型、枚举项都不是由 HR 系统决定的，**任何字段细节都不应在 HR 系统代码中硬编码**。HR 系统只关心「业务上要同步什么类型的数据」，具体的字段名、字段 ID、枚举项都由企微表格的定义决定，并通过后述的「字段映射配置」来连接。

按业务维度划分，需要同步到企微表格的数据包括：

| 业务维度 | 包含的内容（举例） |
|---------|------------------|
| 候选人基本信息 | 姓名、最高学历、院校、工作年限、候选人来源 |
| 应聘信息 | 应聘岗位（关联到企微「职位表」）、面试官（关联到企微「成员表」） |
| 面试安排 | 一面 / 二面面试时间、面试官、面试地点 |
| 面试过程 | 一面 / 二面评价、能力标签、备注 |
| 面试结果 | 面试状态（如：待面试 / 一面通过 / 一面淘汰 / 二面通过 / 二面淘汰 / 待复试 / 拒 offer / 待入职 / 已入职 / 已离职 / 不考虑 等） |
| 录用信息 | 拟入职时间、岗位级别、薪资范围 |
| 入职后变更 | 实际入职时间、离职时间、离职原因 |
| 简历档案 | 建档日期、建档周日期、简历链接 |
| 标题 | 自动拼接的「候选人姓名 - 应聘岗位」 |

> **敏感字段不向企微同步**：候选人的手机号、邮箱等联系方式默认不出现在企微表格里，避免非 HR 角色直接获取联系方式。

## 五、触发节点与同步策略

### 1. 触发时机

| HR 系统节点 | 同步动作 |
|------------|---------|
| 沟通中 → 待面试（HR 点击「预约面试」） | 在企微表格**新增**一条记录 |
| 待面试 → 已面试（HR 点击「面试结束」） | **更新**对应记录的一面信息、面试状态 |
| 已面试 → 已录用 | **更新**对应记录的录用信息、状态 |
| 已面试 → 不合适 | **更新**对应记录的状态 |
| 任何环节 → 取消面试 / 拒 offer / 候选人主动放弃 | **更新**对应记录的状态 |
| 已录用 → 已离职（HR 标记离职并填写离职时间） | **更新**对应记录的状态为「已离职」，并记录离职时间、离职原因 |
| 已录用 → 已离职（**定时触发**：到达离职时间当天） | **更新**对应记录：自动确认离职生效（「已离职」状态、实际离职时间落库） |
| 任一字段在 HR 系统被修改 | **更新**对应记录的相关字段 |

> **定时同步说明**：除了 HR 手动操作触发的「瞬时同步」外，本需求还要求支持**按时间到达 / 到期**触发的定时同步。典型场景：
>
> - 候选人被标记为「已离职」并填写了「离职时间」，到了离职时间当天，系统自动把状态在 HR 系统中生效（从「待离职」变为「已离职」），并同步到企微表格；
> - 后续如「已入职」人员有类似的「转正日」「合同到期日」等时间点到期需要同步状态的场景，都走同一个定时同步机制。
>
> 实现要点：
> - 系统每天定时扫描候选人跟进记录中「即将到期 / 已到期」的时间字段（如「离职时间」「转正时间」）；
> - 扫描到到达时间的记录，按既定状态转换规则更新 HR 系统侧状态，并触发一次同步到企微表格；
> - 定时任务与手动操作的同步走同一套推送链路（异步队列 + 批量），复用限流保护；
> - 定时任务失败按相同重试策略处理（指数退避最多 3 次），失败计入告警日志，可在候选人跟进详情页查看「同步状态」；
> - 定时任务的扫描窗口（如「每天凌晨 02:00 扫描次日到期的记录」）可在配置页调整。

### 2. 新增 vs 更新

- **新增**：候选人第一次进入「待面试」时，往企微表格插一条记录。
- **更新**：后续任何字段或状态变化，都走更新接口（同一个候选人同一份投递在企微表格里只对应一条记录）。

**沟通中阶段不触发同步**：HR 频繁联系阶段不打扰协作者，只在到达「待面试」及之后阶段才同步。

**已离职场景示例**：

```
HR 在「已录用」人员列表标记某人离职，填写离职时间 = 2025-09-15、离职原因
        ↓
该候选人进入「已离职」tab，HR 系统同步更新企微表格：状态值变为「已离职」枚举，
新增离职时间、离职原因字段 → 推送成功
        ↓
时间到了 2025-09-15 当天，系统定时任务扫描到该候选人「离职时间」已到期
        ↓
HR 系统侧自动确认离职生效（实际离职时间 = 2025-09-15），并触发一次同步到企微表格
        ↓
企微表格的状态字段保持「已离职」，实际离职时间字段更新
```

> 整个过程中，HR 系统侧只是配置了「离职时间字段 → 企微离职时间字段」、「HR 系统的「已离职」状态 → 企微的「已离职」枚举」两条映射，**没有写任何与「已离职」状态相关的同步代码**。如果将来 HR 系统再加一个「待离职」中间状态，只需在映射表里补一行即可。

### 3. 同步方向

- **单向同步**：HR 系统 → 企微智能表格。
- 企微表格作为「只读视图」，不反向修改 HR 系统（如果未来需要双向同步，另起需求）。

### 4. 状态字段（选项卡 / 单选）的同步机制

> 业务方常问的一个问题：「企微端的状态是一个选项卡，HR 系统以后新增 / 减少状态（比如本次新增「已离职」），企微那边能不能跟着改？」
>
> 答案是：**完全可以，且整套机制都在配置化范围内，不需要改代码**。具体说明：

- **字段类型自动识别**：企微智能表格的状态字段是「单选」类型（`type: "single_select"`，带 `enum` 列表）。导入示例 JSON 时，系统自动识别到该字段类型及枚举值，AI 智能映射会优先推荐「HR 系统跟进状态字段 ↔ 企微状态字段」的对应关系，置信度高。
- **HR 系统新增状态后重新对齐**：HR 系统新增「已离职」状态后（例如本次新增「已离职」tab），企微表格的状态字段就需要新增对应枚举值。整体流程：
  1. 业务方在企微表格的状态字段上**新增「已离职」枚举值**（人工操作，企微不支持程序化新增枚举）；
  2. HR 系统配置页出现「企微字段枚举有变化」提示（新增了「已离职」枚举）；
  3. HR 在映射配置页补充枚举映射：HR 系统「已离职」 → 企微「已离职」；
  4. AI 智能映射会基于枚举文本相似度自动推荐这一步，HR 确认即可；
- **HR 系统重命名状态**：同样只需在企微表格上修改枚举文本，然后在配置页调整映射。
- **不需要改代码**：状态字段的字段 ID、字段类型、枚举文本和映射关系全部在配置页维护，HR 系统业务的「新增 tab / 新增状态」只需要在企微表格侧同步新增枚举 + 配置页补充映射即可上线。

> **关键约束**：HR 系统永远不预判企微表格有哪些状态值，HR 系统侧的状态字段独立维护「自己的枚举集合」，在同步时通过**配置化的枚举映射表**翻译成企微侧的状态文本。这样即使将来 HR 系统或企微侧任意一方调整状态，都不会影响对方，**唯一需要变更的是配置页里的枚举映射**。

## 六、关键挑战：企微字段会变

> 这是本需求最重要的一条背景。**当前企微这份表格只是初步方案的验证稿**，未来一定会有以下变化：
>
> 1. 字段新增 / 删除 / 改名（如「面试状态」枚举值调整）；
> 2. 字段类型变化（如「主面试官」从文本字段改成关联字段）；
> 3. 整体切换到另一份新文档（Webhook 地址、字段 ID 全部变更）；
> 4. 业务方在企微端可能临时加字段、改字段名。
>
> 因此本需求**必须把字段映射做成可配置**，且必须支持 AI 辅助映射，让 HR / 管理员在企微字段变化时能够快速重新对齐，**绝不允许把字段 ID、字段名、枚举值硬编码到 HR 系统代码里**。

## 七、企微字段映射可配置（核心能力）

### 1. 系统配置页：企微同步配置

在「系统设置」下新增「企微同步配置」页面，作为整个同步功能的总入口，提供：

- **Webhook 地址配置**：HR / 管理员可在此维护企微表格的 Webhook 地址，支持 [测试连接] 验证是否畅通。
- **字段映射配置**：HR 系统字段 ↔ 企微字段 的对应关系，全部以配置项形式保存，不在代码中硬编码。
- **同步状态总览**：今日新增数、今日更新数、失败数（可点击查看详情）。

### 2. 三种配置方式

#### 2.1 手动配置（兜底）

HR / 管理员在配置页直接编辑每一行映射：下拉选择企微字段、对应 HR 系统字段、转换规则。

#### 2.2 导入示例自动配置（推荐）

粘贴 / 上传企微智能表格「接收外部数据」示例 JSON（即 `schema + add_records` 那段示例数据），系统自动解析出企微字段定义（标题、类型、枚举），并进入 AI 智能映射。**特别适合切换到新文档时使用**。

#### 2.3 AI 智能映射

**触发时机**：

- 首次配置同步时
- 切换到新企微文档时（Webhook 变更、字段 ID 全部重置）
- 现有文档字段调整后（个别字段被改名 / 新增 / 删除）
- 管理员手动点击触发

**AI 行为**：

- 输入：企微字段定义（标题、类型、枚举）+ HR 系统候选人 / 跟进模型上的可用字段列表 + 历史映射数据
- 输出：每行一个映射建议，含置信度（高 / 中 / 低）和简要说明
- **HR 系统无对应字段时，AI 不强行匹配**，标记为「未匹配」，由 HR 决定：留空 / 填固定值 / 后续补字段
- AI 推荐结果**需 HR 确认后才生效**，不允许 AI 自动写入映射
- **每次确认后的映射关系作为历史映射沉淀**，下次切换 / 调整文档时 AI 优先复用

### 3. 字段类型支持范围

根据企微智能表格官方文档（[添加记录](https://developer.work.weixin.qq.com/document/path/101240)），Webhook 写入支持的字段类型：

| 类别 | 类型 | 写入形态 |
|-----|------|---------|
| 基础 | 文本 / 数字 / 复选框 / 进度 / 百分数 / 货币 | 直接传值 |
| 选项 | 单选 / 多选 | 传 `[{"text":"选项内容"}]`；HR 系统枚举未命中时默认「留空 + 告警」 |
| 关联 | 成员（企微 user_id） | 传 `[{"user_id":"..."}]` |
| 关联 | **跨表关联字段**（如应聘岗位 → 企微职位表） | 传被关联表的 `record_id` 数组 |
| 时间 | 日期（毫秒时间戳或格式化字符串） | 时间戳或 `yyyy-mm-dd hh:mm:ss` |
| 资料 | 链接 / 电话 / 邮箱 / 图片 / 地理位置 / 条码 | 按对应格式传值 |
| 不支持 | 公式 / 自动编号 / 创建人 / 创建时间 / 最后编辑人 / 最后编辑时间 / 群聊 / 文件 | **跳过该字段**，不影响其他字段同步 |

#### 3.1 跨表关联字段（重点关注）

**企微表格里常见的「应聘岗位」「主面试官」等，都是关联字段**，写入时传的不是名称，而是**被关联表中对应记录的 `record_id`**。

> 这意味着 HR 系统必须先知道企微「职位表」「成员表」里对应记录的 record_id，否则关联字段无法写入。

**解决办法：HR 系统侧维护关联档案的同步机制**：

| 关联目标 | 触发时机 | 做法 |
|---------|---------|------|
| 企微「职位表」 | HR 系统新增 / 修改职位 | 推一条记录到企微职位表，把返回的 `record_id` 保存到 HR 系统职位的扩展字段 |
| 企微「成员表」 | HR 系统用户配置企微 user_id | 推一条记录到企微成员表，把返回的 `record_id` 保存到 HR 系统用户的扩展字段 |
| 候选人记录写入 | 同步候选人时 | 通过 `position_record_id` / `user_record_id` 写入关联字段 |

**关联失败兜底**：关联目标记录不存在时，该关联字段留空 + 日志告警，不影响其他字段同步。

#### 3.2 单选 / 多选字段

- 企微接收到未在新枚举中的值时，会自动新增同名选项，长期会污染企微枚举表。
- 因此本需求要求：**HR 系统枚举 → 企微枚举的映射表必须维护**，枚举值未命中时默认「留空 + 告警」，由 HR 手动补映射或调整。
- 枚举值映射也走 AI 智能映射。

### 4. 字段变更的应对策略

| 企微侧变化 | 系统应对 |
|-----------|---------|
| 字段被改名 | 标题相似度匹配历史映射，自动更新字段 ID；匹配不上则标红告警 |
| 字段被删除 | 该映射行标红告警「企微字段已不存在」，同步跳过该字段 |
| 字段被新增 | 提示「检测到新增字段」，引导进入 AI 智能映射 |
| 整体切换到新文档 | 替换 Webhook 地址后，系统提示「文档已变更」，引导走「导入示例自动配置」重新配置 |

### 5. 典型场景示例

#### 场景 A：初次配置同步

```
1. HR 在「系统设置 → 企微同步配置」粘贴 Webhook 地址，点击 [测试连接]
2. 点击 [导入示例自动配置]，粘贴企微提供的示例 JSON
3. 系统解析 schema，展示所有字段
4. AI 自动推荐 HR 系统字段映射，HR 逐行确认
5. 保存配置 → 同步功能上线
```

#### 场景 B：企微新增了一个字段

```
1. 系统检测到企微 schema 变化，提示「新增 N 个字段」
2. HR 点击提示，进入 AI 智能映射
3. AI 判断：HR 系统无对应字段 → 标记为「未匹配」
4. HR 选择「留空，不同步该字段」或先在 HR 系统补字段再回填
```

#### 场景 C：团队整体切换到新文档

```
1. 管理员在企微创建新文档，拿到新 Webhook
2. 在 HR 系统配置页替换 Webhook 并 [测试连接]
3. 系统提示「检测到文档变更，请重新配置字段映射」
4. 走「导入示例自动配置」流程，AI 复用历史映射推荐新文档字段
5. HR 确认后保存
```

## 八、性能与稳定性

根据企微官方文档的频率限制：

> 单工作表 Webhook 累计添加（更新）记录 ≤ **3000 条/分钟**
> 单文档所有 Webhook 累计添加（更新）记录 ≤ **10000 条/分钟**

为避免触发限流，实现层必须做：

- **异步队列**：状态变更触发的同步请求统一进入异步队列，平滑突发流量，不阻塞 HR 系统操作。
- **批量写入**：短时间内多个候选人同步时，系统侧聚合后批量推送，避免单次 1 条 / 请求的高频调用。
- **失败重试**：HTTP 5xx 或网络错误按指数退避重试（最多 3 次）；4xx 错误记录日志告警，不重试。
- **限流熔断**：检测到响应触发限流时主动降速，避免雪崩。
- **同步状态可查**：失败时记录详细日志（候选人 ID、推送时间、错误码、错误信息），HR 在系统后台可查看失败原因并可手动「重新同步」。

## 九、业务规则

| # | 规则 | 说明 |
|---|------|------|
| 1 | 同步触发点 | 仅在候选人进入「待面试」及之后阶段才同步；「沟通中」阶段不同步 |
| 2 | 一条记录原则 | 同一个候选人同一份投递给企微表格只产生一条记录，状态变化走更新 |
| 3 | 单向同步 | 仅 HR 系统 → 企微，企微端不反向修改 HR 系统 |
| 4 | 频率保护 | 同步必须经异步队列 + 批量发送，避免触发企微每分钟 3000 条限制 |
| 5 | 字段映射可配置 | 企微字段 ID、字段映射、枚举映射、类型转换规则全部在配置页维护，**不允许硬编码到代码里** |
| 6 | AI 辅助映射 | 首次配置、切换文档、字段调整时，由 AI 推荐映射，HR 确认后生效；HR 系统缺字段时标记「未匹配」，由 HR 决定留空 / 固定值 / 补字段 |
| 7 | 字段映射历史 | 每次确认后的映射关系作为历史映射沉淀，下次切换 / 调整文档时 AI 优先复用 |
| 8 | 关联档案同步 | HR 系统新增 / 修改职位时同步到企微职位表；用户配置企微 user_id 时同步到企微成员表；返回的 record_id 持久化保存，作为候选人关联字段的写入依据 |
| 9 | 关联缺失处理 | 关联目标记录不存在时，关联字段留空 + 日志告警，不影响其他字段同步 |
| 10 | 枚举未命中处理 | 单选 / 多选字段未命中时默认「留空 + 告警」，避免自动新增选项污染企微枚举表 |
| 11 | 不支持字段跳过 | 字段类型为公式 / 自动编号 / 创建人 / 创建时间 / 最后编辑人 / 最后编辑时间 / 群聊 / 文件时，同步跳过该字段 |
| 12 | 敏感字段处理 | 候选人手机号、邮箱等敏感字段不同步到企微，通过配置项控制，默认关闭 |
| 13 | 重新同步入口 | 候选人跟进详情页提供「重新同步到企微」按钮，HR 可手动触发一次全量同步该候选人 |
| 14 | 失败可观测 | 同步失败必须记录日志（候选人 ID、推送时间、错误码、错误信息），并支持 HR 在系统后台查看「同步状态」 |
| 15 | 定时到期同步 | HR 系统支持按时间字段到期触发同步（如「离职时间」到达当天），系统按既定状态转换规则自动更新 HR 侧状态并同步到企微，与手动同步共用同一推送链路（异步队列 + 限流保护） |
| 16 | 定时扫描配置 | 定时扫描窗口可在配置页调整（默认扫描次日到期的记录），可关闭 / 启用 |
| 17 | 状态字段解耦 | HR 系统侧状态枚举与企微表格侧状态枚举完全解耦，通过配置化的枚举映射表翻译；任何一方新增 / 修改 / 删除状态均不影响对方，不需要改代码 |
| 18 | 新增 tab 无需改代码 | HR 系统新增子页面 tab（如「已离职」）时，只需在企微表格给状态字段新增对应枚举，再在配置页补充枚举映射即可上线 |

## 十、验收标准

### 同步触发

1. HR 在「沟通中」点击「预约面试」后，候选人进入「待面试」列表，企微智能表格同步新增一条记录
2. 候选人面试状态变化（待面试 / 已面试 / 已录用 / 不合适 / 拒 offer / 取消面试等）后，企微表格对应记录的状态字段同步更新
3. 任何字段在 HR 系统被修改后，企微表格对应字段同步更新
4. 候选人处于「沟通中」阶段时，不同步到企微表格

### 字段映射可配置（核心）

5. 系统设置下新增「企微同步配置」页面，可配置 Webhook 地址、字段映射、枚举映射、类型转换规则
6. 字段映射、字段 ID 全部配置化保存，**不在业务代码中硬编码**（更换字段 ID 无需发版）
7. 提供「导入示例自动配置」能力：粘贴企微「接收外部数据」示例 JSON 即可一键导入字段定义
8. 提供「AI 智能映射」能力：基于企微字段定义 + HR 系统字段列表 + 历史映射，AI 推荐字段映射并标注置信度
9. HR 系统无对应字段时 AI 标记为「未匹配」，由 HR 手动选择留空 / 固定值 / 待补字段
10. AI 推荐结果需 HR 确认后才生效，不允许 AI 自动写入映射
11. 字段映射历史被沉淀，下次切换 / 调整文档时 AI 优先复用
12. 字段类型转换规则（直接取值 / 拼接 / 枚举映射 / 时间戳 / 企微 user_id 转换等）以配置项呈现，无需改代码
13. 企微字段被改名 / 删除时系统标红告警「字段已不存在」，同步跳过该字段
14. 企微字段被新增时系统提示「检测到新增字段」，引导进入 AI 智能映射
15. 整体切换到新文档时（Webhook 地址变更），系统提示「文档已变更」，可走「导入示例自动配置」重新配置

### 关联字段 / 跨表

16. 关联字段配置页可设置：关联目标表、关联依据字段、单选 / 多选属性、未匹配时的处理策略
17. HR 系统新增 / 修改职位时，自动推送一条记录到企微「职位表」，把返回的 record_id 持久化保存在 HR 系统
18. HR 系统用户配置企微 user_id 时，同步推送一条记录到企微「成员表」，把返回的 record_id 持久化保存
19. 候选人记录写入时，关联字段（应聘岗位 / 面试官等）按 record_id 正确写入企微
20. 关联目标记录不存在时，关联字段留空并在日志中告警「关联目标记录不存在」

### 单选 / 多选字段

21. 单选 / 多选字段支持枚举值映射表配置（HR 系统枚举 ↔ 企微枚举）
22. 枚举值映射走 AI 智能映射，HR 确认后生效
23. 枚举值未命中时，按配置项默认行为处理（推荐「留空 + 告警」，避免自动新增选项污染企微枚举表）

### 不支持字段

24. 企微字段类型为公式 / 自动编号 / 创建人 / 创建时间 / 最后编辑人 / 最后编辑时间 / 群聊 / 文件时，配置页提示「该字段类型不支持 Webhook 写入，已自动跳过」
25. 不支持字段在同步时跳过，不影响其他字段同步

### 性能与稳定性

26. 同步请求走异步队列，不阻塞 HR 系统的状态变更操作
27. 同步失败时按指数退避重试最多 3 次，仍失败则记录日志并保留失败状态
28. 同步频率控制在企微每分钟 3000 条限制以内（建议预留 20% 缓冲，目标 ≤ 2400 条/分钟）
29. 单次批量推送条数可配置（建议 50 条/批），避免单请求体过大

### 可观测与可维护

30. 候选人跟进详情页可查看「企微同步状态」（成功 / 失败 / 同步中），失败时显示错误原因
31. 候选人跟进详情页提供「重新同步到企微」按钮，触发一次该候选人的全量同步
32. 系统后台提供同步记录查询页（按候选人、状态、时间筛选），便于排查同步问题

### 身份映射

33. HR 系统用户表配置企微 user_id 后，面试官字段能正确填充
34. 未配置企微 user_id 的面试官对应字段留空，不报错
35. HR 系统候选人跟进记录 ID 与企微智能表格记录 ID 正确关联，首次新增后 record_id 持久化保存

### 状态字段（选项卡 / 单选）同步

36. 企微端的状态字段（single_select）能被 AI 智能映射自动识别，并推荐 HR 系统跟进状态字段作为对应映射
37. 业务方在企微表格新增枚举（如「已离职」）后，HR 系统配置页提示「企微字段枚举有变化」，引导 HR 补充枚举映射
38. HR 系统或企微侧任意一方新增 / 删减 / 重命名状态值，**不需要改代码**，只需在配置页调整枚举映射即可上线
39. HR 系统新增子页面 tab（如本次新增「已离职」tab）时，状态字段同步机制自动覆盖，无需额外开发

### 定时到期同步

40. 候选人被标记为「已离职」并填写「离职时间」后，到了离职时间当天，系统自动把状态在 HR 系统中生效并同步到企微表格（状态变为「已离职」）
41. 定时扫描窗口可在配置页调整（如「每天凌晨 02:00 扫描次日到期的记录」），可关闭 / 启用
42. 定时触发与手动同步复用同一推送链路（异步队列 + 批量 + 限流 + 重试），失败按相同策略处理并可查看「同步状态」
