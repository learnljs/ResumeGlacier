
# 简历信息从 Email 库中独立出来

## 一、需求背景

### 1.1 当前问题

目前系统中，**简历被当作邮件的附属品**，主要表现为：

1. **概念混淆**：在业务逻辑上，简历只是"邮件的附件"，但实际业务中，**简历才是核心资产**
2. **数据风险**：删除邮件可能导致简历数据丢失
3. **无法统一管理**：简历依附在邮件上，无法形成统一的公司简历库
4. **生命周期不对等**：
   - 邮件的生命周期：收取 → 存储 → 归档
   - 简历的生命周期：收取 → 解析 → 匹配 → 筛选 → 跟进 → 录用/拒绝

### 1.2 核心需求

建立**统一的公司简历库**：
- 所有简历自动化收集，不依赖人工操作
- 简历成为独立的业务对象，有自己完整的生命周期
- 简历不再依附于邮件，删除邮件不影响简历

---

## 二、业务概念澄清

### 2.1 Email 和 Resume 的关系（改变前）

**当前理解（有问题）**：
```
邮件（容器）
  └── 简历（邮件里的一个附件）
```
→ 如果删除邮件，简历也跟着消失

### 2.2 Email 和 Resume 的关系（改变后）

**新的理解**：
```
邮件（一个线索来源）
    ↓（引用关系）
简历（独立的业务对象，存放在统一简历库）
```
→ 邮件只是简历的"来源"之一，删除邮件不影响简历库中的简历

---

## 三、业务流程变更

### 3.1 邮件收取简历流程（保持不变，但概念调整）

**流程**：
```
1. 系统从招聘软件收取邮件
2. 系统记录邮件信息（谁发的、什么时间、标题是什么）
3. 系统检查邮件里的简历附件
4. 如果有有效简历：
   - 系统在简历库中创建一份简历
   - 简历上标记：来源是"这封邮件"
5. 简历进入后续流程（解析、匹配、筛选...）
```

**关键点**：
- 邮件记录和简历记录是分开的，只是简历上记了"我是从这封邮件来的"
- 删除邮件不会删除简历库中的简历

---

## 四、核对标准（验收条件）

### 4.1 核心功能核对

| 检查项 | 标准 |
|-------|------|
| **邮件收取简历** | 能正常从邮件收取简历，功能不受影响 |
| **邮件删除** | 删除某封邮件，不会影响从该邮件创建的简历 |
| **简历溯源** | 查看简历时，能看到这份简历是从哪封邮件来的 |
| **简历生命周期** | 简历可以被多次重新解析、重新筛选，不受邮件影响 |
| **统一简历库** | 所有简历集中在一个库中管理，不再分散在各邮件下 |

### 4.2 业务数据核对

| 检查项 | 标准 |
|-------|------|
| **历史数据迁移** | 现有所有简历都保留，能正常查看和操作 |
| **来源信息** | 所有简历都有明确的来源标识（哪封邮件） |
| **数据完整性** | 简历的所有历史操作记录（解析、筛选、跟进）都完整保留 |

---

## 五、业务价值

| 方面 | 改进前 | 改进后 |
|------|-------|-------|
| **简历管理** | 简历分散在各邮件中 | 统一简历库，集中管理 |
| **数据安全** | 删除邮件可能丢简历 | 简历独立保存，历史可追溯 |
| **功能扩展** | 简历功能受邮件限制 | 可以为简历库开发更多功能（多版本、归档、导出等） |
| **资产价值** | 简历只是邮件附件 | 简历是公司核心人才资产 |

---

## 六、实施建议

- 保持现有功能完全不变
- 简历上新增"来源信息"字段（现有数据填对应邮件信息）
- 用户无感知
