# 权重模型与职位进行关联需求

## 一、需求背景

当前权重模型作为独立模块放在系统设置中，所有职位共用同一套默认模型，无法实现不同职位评分规则的差异化配置。

由于权重模型数据量较小，独立成页面反而增加了 HR 的操作路径。

**目标**：将权重模型管理完全融合到职位管理中，删除独立页面，让每个职位直接维护属于自己的权重模型。

## 二、核心改动

### 1. 页面整合

- **删除**：系统设置中的独立权重模型管理页面
- **融合**：权重模型管理完全内嵌到职位管理页面中

### 2. 职位编辑页面结构调整

- **主页面仅作为入口**：职位管理主页面展示职位列表和"新增职位"入口
- **新增/编辑职位进入独立页面**：无论是新增还是编辑某个职位，都进入一个独立的全屏编辑页面，一个职位对应一个独立页面，页面内完整展示该职位的所有信息（职位基础信息 + 权重模型管理区域）
- **权重模型管理同页面完成**：在职位编辑页面内，权重模型管理与职位信息编辑在同一页面完成，通过"+"按钮新增权重模型，无需跳转或弹窗

### 3. 职位内嵌模型管理

职位编辑页面内的权重模型管理区域分为两个分组：

| 分组 | 说明 |
|------|------|
| 初筛模型分组 | 维护多个初筛模型，**只能指定一个作为默认** |
| 冰山模型分组 | 维护多个冰山模型，**只能指定一个作为默认** |

每个分组支持的操作：通过 **"+"按钮新增**（填写模型名称、各维度权重后保存到该职位下）、**编辑**（修改名称或权重）、**删除**（默认模型需先切换默认绑定才能删除）、**设为默认**（自动取消其他模型的默认标记）。

### 4. 职位默认权重模型绑定

职位信息框中新增两个绑定字段，可选范围限定为该职位自身的模型列表：

| 字段 | 用途 |
|------|------|
| 默认初筛模型 | 用于初筛阶段评分 |
| 默认冰山模型 | 用于冰山阶段评分 |

**新建职位默认值**：系统预置有"初筛-默认模型"和"冰山-默认模型"两份默认权重模型（作为模板），新建职位时自动以这两份默认模型为模板初始化该职位下的默认权重模型，并分别设为该职位的默认初筛模型和默认冰山模型。HR 可在该职位下调整、修改、新增或切换默认。

### 5. 模型与职位的关系

- 每个职位可维护多个初筛模型和多个冰山模型，按需配置
- **每个职位在每一类（初筛/冰山）下有且仅有一个默认权重模型**，明确唯一
- 模型归属于职位，删除职位时模型一并删除
- 初筛模型只能绑定"默认初筛模型"字段，冰山模型只能绑定"默认冰山模型"字段

### 6. 职位状态管理规则

职位采用"启用 / 停用 / 已删除"三态管理。

#### 6.1 三种状态

| 状态 | 说明 |
|------|------|
| **启用中** | 正常招聘中的职位 |
| **停用** | 历史归档的职位，置灰显示，不再接受新简历投递，可重新启用 |
| **已删除** | 物理删除，仅适用于无关联简历的职位，删除后数据库不存在 |

#### 6.2 简历数判断规则

- **只要存在过任何简历关联，都视为"有关联"**（不考虑候选人当前业务状态）
- 简历数 > 0 → 不能物理删除，只能停用
- 简历数 = 0 → 可以物理删除

#### 6.3 状态与操作权限矩阵

| 状态 | 编辑职位信息 | 管理权重模型 | 停用 | 启用 | 删除 |
|------|------------|------------|------|------|------|
| 启用中（简历数=0） | ✓ | ✓ | ✓ | - | ✓ |
| 启用中（简历数>0） | ✓ | ✓ | ✓ | - | ✗（置灰禁用） |
| 停用 | ✗ | ✗ | - | ✓ | ✗ |

#### 6.4 双向切换机制

- **停用 ↔ 启用支持双向来回切换**，确保业务上可随时重启历史职位的招聘
- 停用后**锁定**：职位基础信息和权重模型都不能修改，必须先"启用"才能修改

#### 6.5 提示文案

| 场景 | 提示信息 |
|------|---------|
| 删除按钮置灰悬浮提示 | "该职位存在 N 条关联简历，不可删除，请先停用" |
| 停用操作二次确认 | "停用后该职位不再接受新简历投递，已有关联简历不受影响" |
| 启用操作二次确认 | "启用后该职位将重新接受新简历投递" |

#### 6.6 删除规则

- 删除前系统自动校验简历数，必须 = 0 才允许执行物理删除
- 删除职位时，该职位下的所有权重模型一并清理

## 三、列表与详情页评分展示

### 1. 核心原则

列表和详情页的得分都**根据候选人投递职位的默认权重模型**计算，不同候选人投递不同职位时，各自按各自职位的模型计算。

### 2. 列表评分展示

| 列表 | 使用的模型 |
|------|-----------|
| 已筛选简历列表 | 投递职位的默认初筛模型 |
| 沟通中列表 | 投递职位的默认初筛模型 |
| 待面试列表（仅知识、技能评分） | 投递职位的默认初筛模型 |
| 待面试列表（6 个维度均有评分） | 投递职位的默认冰山模型 |
| 已面试列表 | 投递职位的默认冰山模型 |

### 3. 简历详情页加载规则

| 进入场景 | 默认加载的模型 |
|---------|--------------|
| 从已筛选/沟通中/待面试列表进入（仅知识、技能评分） | 岗位的默认初筛模型 |
| 从待面试/已面试列表进入（6 个维度均有评分） | 岗位的默认冰山模型 |

**横向对比**：保留切换不同权重模型查看差异的功能，可选范围限定为该岗位自身模型列表，切换不影响职位默认配置。

## 四、页面详细设计

### 1. 职位管理页面

职位管理由**主页面**、**职位编辑页面**、**已停用职位子页面**三部分组成：

- **主页面（入口）**：只展示所有"启用中"的职位列表，提供"新增职位"按钮和"已停用职位"入口按钮，不在列表中展开或展示职位详细信息
- **职位编辑页面（独立页面）**：点击"新增"或列表中某个职位的"编辑"按钮后，进入一个独立的全屏编辑页面，一个职位对应一个独立页面，页面内容包括：
  - 职位基础信息表单（完整展示该职位的所有信息）
  - 权重模型管理区域（与职位信息同页面），按"初筛模型"和"冰山模型"两个分组展示，每个分组通过"+"按钮新增模型，下方列表展示该职位下的所有模型（模型名称、权重配置、默认标记、操作按钮）
  - 操作按钮：停用、删除（按二.6 状态管理规则控制可用性）
- **已停用职位子页面**：从主页面"已停用职位"入口跳转进入，展示所有"停用"状态的职位，置灰显示，提供"启用"按钮将职位切换回启用状态（详见二.6 状态管理规则）

### 2. 跟进管理页面评分展示

- 已筛选简历列表、沟通中列表的初筛得分：使用候选人投递职位的默认初筛模型计算
- 待面试列表得分：根据当前已填维度自动切换（仅知识/技能用初筛模型，6 个维度齐全用冰山模型）
- 已面试列表的综合得分：使用候选人投递职位的默认冰山模型计算

### 3. 简历详情页评分展示

- 默认加载：按进入场景对应的默认模型展示（详见三.3）
- 雷达图和得分计算区域均基于职位的默认权重模型展示
- 权重模型选择区域：下拉框默认选中相应默认模型，切换其他模型实时重新计算得分用于横向对比（可选范围限定为该岗位自身模型列表）

## 五、核心优势

1. **管理路径更短**：HR 在编辑职位时即可完成模型的全部管理操作
2. **职位评分差异化**：每个职位可配置符合自身特点的初筛/冰山模型
3. **职责边界清晰**：模型归属具体职位，删除职位时模型一并清理
4. **配置更直观**：所见即所得，无需跨页面查找
5. **默认模型唯一**：每个职位在每一类下仅有一个默认权重模型，规则明确

## 六、验收标准

1. 删除系统设置中的独立权重模型管理页面
2. 职位管理主页面展示职位列表和"新增职位"入口按钮
3. 新增/编辑职位进入独立的全屏编辑页面，一个职位对应一个独立页面，完整展示职位所有信息
4. 权重模型管理与职位信息编辑在同一页面，通过"+"按钮新增权重模型
5. 权重模型管理按"初筛模型"和"冰山模型"两个分组展示
6. 每个分组下可独立新增、编辑、删除属于该职位的模型，支持维护多个
7. **每个职位在每一类（初筛/冰山）下有且仅有一个默认权重模型**，切换默认时自动取消其他模型的默认标记
8. 默认模型标星高亮且不可直接删除，需先切换默认绑定
9. 新建职位时，以系统预置的"初筛-默认模型"和"冰山-默认模型"为模板初始化该职位的默认权重模型
10. 职位信息框中"默认初筛模型"字段可选范围为该职位自身的初筛模型列表
11. 职位信息框中"默认冰山模型"字段可选范围为该职位自身的冰山模型列表
12. 切换默认绑定后，列表和详情页自动使用新选中的模型计算得分
13. 列表中所有候选人得分按候选人投递职位的默认权重模型计算
14. 已筛选简历列表、沟通中列表的初筛得分使用投递职位的默认初筛模型
15. 待面试列表仅知识/技能评分时用默认初筛模型，6 个维度齐全时用默认冰山模型
16. 已面试列表的综合得分使用投递职位的默认冰山模型
17. 简历详情页按进入场景加载对应的默认模型展示（仅知识/技能用初筛，6 维度齐全用冰山）
18. 简历详情页保留切换不同模型查看差异的功能，可选范围限定为该岗位自身模型列表
19. 切换候选人投递的职位或修改职位默认模型后，列表和详情页评分自动重新计算
20. 职位管理主页只展示"启用中"的职位，提供"新增职位"和"已停用职位"入口按钮
21. 职位编辑页面提供"停用"和"删除"按钮，按状态管理规则控制可用性
22. 已停用职位子页面从主页跳转进入，展示所有"停用"职位，置灰显示，提供"启用"按钮
23. 停用 ↔ 启用支持双向来回切换，停用后锁定职位信息和权重模型（不可修改）
24. 删除按钮仅对"启用中且简历数 = 0"的职位可点击，否则置灰禁用
25. 简历数 > 0 时删除按钮悬浮提示"该职位存在 N 条关联简历，不可删除，请先停用"
26. 停用操作二次确认提示"停用后该职位不再接受新简历投递，已有关联简历不受影响"
27. 启用操作二次确认提示"启用后该职位将重新接受新简历投递"
28. 删除职位为物理删除（仅适用于简历数 = 0 的职位），删除时该职位下的所有权重模型一并清理
