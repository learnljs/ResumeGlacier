# 跟进看板设计

> **一句话**：数据概览页上的一块招聘跟进看板，让 HR 按所选岗位（可多选、可全部）一眼看清「当前各状态有多少投递」「沟通中的联系触达情况如何」「按所选时间段看流转了多少、推进到哪」。  
> **基线**：状态定义对齐《[简历状态v2.md](简历状态v2.md)》的 10 个状态（沟通中 / 待面试 / 已面试 / 已发offer / 待入职 / 已入职 / 已离职 / 拒offer / 取消面试 / 不合适）；「是否联系上」属性定义见《增加是否联系上属性.md》。

---

## 一、背景与目标

### 1.1 为什么做

HR 日常巡检和阶段性复盘时，需要按岗位了解当前各状态的投递数、沟通中的联系触达情况、以及所选时间段内的流转情况，但这些信息分散在各岗位、各状态 Tab 里，HR 要逐个点开数，缺乏一个整体视图。

### 1.2 目标

在「数据概览」页面按所选岗位展示本看板的三类统计，无需逐个点开 Tab。

### 1.3 范围界定

本看板包含三类统计，统计范围 = **所选岗位的投递**（详见 §三）：

- **当前状态统计**：10 个状态卡，展示当前各状态的投递数。
- **是否联系上统计**：仅统计「沟通中」状态的投递。
- **流转图**：按所选时间段展示所选范围内的流转情况。

---

## 二、看板整体布局

> **权限与交互范围**：看板为**纯只读视图**，交互仅切换统计维度（岗位选择、时间段），不产生任何数据变更。

> 看板整体布局见《跟进看板-数据概览原型.html》示例页面：顶部依次为**时间段选择器**（起止日期手动输入 + 周快捷选取，默认本周）与**岗位选择下拉多选**（可多选、含「全部岗位」，默认全部岗位），下方依次为 10 个状态卡、「是否联系上」环形图与流转图（卡片节点图）；看板权限与「数据概览」页面一致。三类统计（状态卡 / 是否联系上 / 流转图）**均受**岗位选择与时间段两个筛选维度共同控制。

---

## 三、筛选维度与统计范围

> 时间段与岗位选择并列为看板**全局筛选维度**，同时控制三类统计（状态卡 / 是否联系上 / 流转图）的数据源。

### 3.1 岗位选择

> **下拉交互规则**：勾选任一具体岗位时自动取消「全部岗位」勾选；全部取消勾选时显示空态（不自动恢复「全部岗位」）。

- 看板顶部提供岗位选择下拉多选，可勾选**多个岗位**，也可勾选「全部岗位」；**默认选中「全部岗位」**。
- 下拉选项仅包含**启用中**的岗位（停用 / 已删除的岗位不出现在下拉中）；「全部岗位」= 所有岗位投递的整体情况，后端不过滤启用状态，因此停用 / 已删除岗位与未分配占位评估（`positionId = 'unassigned'`）的投递也会计入。

### 3.2 时间段选择

> 时间段对三类统计的口径详见 §四。

- 看板顶部提供时间段选择，**默认本周（周一至周日）**，包含：
  - **起止日期手动输入**：分别输入开始与结束日期（`YYYY-MM-DD`，含首尾）；起止选同一天即查看单日；结束日期不早于开始日期（非法范围提示并拒绝请求）。
  - **周快捷**：原生周输入框 + 上一周 / 下一周按钮，选择后一键回填起止日期框；周快捷仅作回填，不锁定日期类型。
- 周快捷按自然周（周一至周日）换算；手动修改起止日期即为自定义范围。
- 切换时间段后，三类统计（状态卡 / 是否联系上 / 流转图）全部按新范围重新统计。

### 3.3 统计范围与口径

- **统计单位 = 投递**：候选人对某个岗位的一次投递与跟进记录。同一候选人投递多个岗位时，每个岗位各是一条投递，**独立计数、互不影响**。
- 选中一个岗位：统计该岗位的全部投递。
- 选中多个岗位：合并统计这些岗位的全部投递。
- 选中「全部岗位」：统计所有岗位的全部投递（即整体情况）。
- 时间段同时作用于三类统计的投递集合与流转批次（详见 §四.2 各统计口径）。

---

## 四、三类统计

> **统一口径**：三类统计均受 §三 中岗位选择与时间段两个筛选维度共同控制。本节说明每一类如何在所选投递范围内按口径统计。

### 4.1 当前状态统计卡

**口径**：状态卡展示所选岗位范围内，**所选时间段内进入「已筛选」的投递**中，当前时刻处于各状态的投递**当前快照**数。所选时间段越短、越接近此刻，统计结果越接近"当下"；选更长区间时，看到的是这批投递目前的去向分布。

**卡片定义（10 个状态）**

| #  | 状态卡     | 含义                |
| -- | ------- | ----------------- |
| 1  | 沟通中     | 初次接触，正在跟进         |
| 2  | 待面试     | 等待安排面试            |
| 3  | 已面试     | 面试完成，等待结果         |
| 4  | 已发offer | 已发出 offer，等待候选人回复 |
| 5  | 待入职     | 候选人已确认，等待入职日期     |
| 6  | 已入职     | 候选人已入职            |
| 7  | 已离职     | 候选人入职后又离职         |
| 8  | 拒offer  | 候选人拒绝 offer       |
| 9  | 取消面试    | 候选人或 HR 主动取消面试    |
| 10 | 不合适     | 筛选/跟进后判定不合适       |

**统计规则**

- 每个状态卡的数字 = 所选岗位范围内、所选时间段内进入「已筛选」的投递中当前处于该状态的投递数。
- 切换岗位选择或时间段后，10 个状态卡全部按新范围重新统计。

### 4.2 是否联系上

**口径**：与状态卡一致——展示所选岗位范围内、所选时间段内进入「已筛选」的投递中当前处于「沟通中」状态的投递，三种联系结果的占比与数量。

**状态定义**

| 状态   | 含义              |
| ---- | --------------- |
| 未尝试  | 尚未发起联系          |
| 已联系上 | 已成功触达候选人（不区分意向） |
| 未联系上 | 尝试过但未成功触达       |

**展示与统计范围**

- **展示形式**：环形图，显示三种状态的占比与绝对数量；环形图中心显示「沟通中」投递总数。
- **统计范围**：仅统计所选岗位范围内、所选时间段内进入「已筛选」且当前处于「沟通中」状态的投递；其他状态不展示此字段。

### 4.3 流转图

#### 流转结构

> **数据依赖**：「已筛选」是流转图的批次入口（不新增为第 11 个状态，状态卡不展示），其进入已筛选时间由系统初筛环节写入。流转图统计的时间锚点为**进入「已筛选」的时间**（`screenedAt`，为空回退评估创建时间 `createdAt`）——以投递按该时间落入所选时间段为准，与状态推进时间无关。

**节点**：已筛选、沟通中、待面试、已面试、已发offer、待入职、已入职、不合适、取消面试、拒offer、已离职。已筛选等 7 个状态从左到右排列，不合适 / 取消面试 / 拒offer / 已离职 在对应状态的下方展示，与上方状态用竖线 + ▼ 连接。

> 「已筛选」= 投递通过初筛、尚未开始跟进；它不出现在上方状态卡中（状态卡只统计已进入跟进的 10 个状态），仅作为流转图的批次入口。

**流转路径**（每条路径可能从多个上游状态流入）：

```
正向推进：已筛选 → 沟通中 → 待面试 → 已面试 → 已发offer → 待入职 → 已入职

各状态向下流失 / 终止（同一个下游状态会从不同上游各出现一次）：
  已筛选　→ 不合适
  沟通中　→ 不合适
  待面试　→ 取消面试
  已面试　→ 不合适
  已发offer → 拒offer
  待入职　→ 拒offer
  已入职　→ 已离职
```

> 每个状态为一个节点；节点下方按实际发生的流转方向列出下游状态，并标注该路径的数量（如「已筛选 → 沟通中 28」「已筛选 → 不合适 2」）。不合适 / 拒offer / 取消面试 / 已离职 会从不同上游各出现一次。

#### 统计规则（按时间段）

**核心思路**：把**所选时间段内首次进入「已筛选」的投递视为一批**，用流转图展示这批投递从「已筛选」出发，各自流向了哪里——最终走到了哪个状态。

**每条流转线的数量** = 这批投递中，从上一状态流转到下一状态的数量（被回退撤销的流转不算，不区分回退原因）。

**示例**（本周 30 条投递这批）：

```
正向推进（到达数量）：已筛选(30) → 沟通中(28) → 待面试(12) → 已面试(7) → 已发offer(3) → 待入职(1) → 已入职(0)

各状态向下流失 / 终止（流出数量）：
  已筛选　→ 不合适    2
  沟通中　→ 不合适    3
  待面试　→ 取消面试  1
  已面试　→ 不合适    0
  已发offer → 拒offer   2
  待入职　→ 拒offer   0
  已入职　→ 已离职    0

（沟通中仍有 13 条停留、待面试 4 条、已面试 4 条未往下走；已发offer / 已入职 停留 0，待入职停留 1。）
```

> 「停留」= 到达数量 − 流出数量，即仍未往下走、留在该状态的投递数。本例沟通中 13、待面试 4、已面试 4；已发offer / 已入职 停留 0，待入职停留 1。

**其他规则**：

- **这批怎么圈定**：按投递进入「已筛选」的时间（`screenedAt`，为空回退 `createdAt`）落入所选时间段内的计入；`evaluationId` 为空的历史记录按记录创建时间兜底圈定。流转图从「已筛选」出发，所以「已筛选」节点数量 = 这批总数。
- **节点数量**：这批投递中**曾经到达**该状态的数量（同一投递只算一次，多次到达也只算一次）= 流入该节点的各条线数量之和。
- **时间段交互**：时间段控件见 §3.2（默认本周；手动起止 + 周快捷；结束不早于开始；切换后刷新流转图）。所选时间段内没有投递时，各节点数量显示为 0。
- **展示形式**：卡片节点图——已筛选、沟通中、待面试、已面试、已发offer、待入职、已入职 7 个状态从左到右各排一张卡片，卡片内三行依次是状态名、到达数量、「停留」数字（如沟通中 28 到达 / 停留 13；停留 = 到达数量 − 流出数量，仍未往下走、留在此处的投递数）；卡片间用 → 表示正向推进。不合适 / 取消面试 / 拒offer / 已离职 在对应状态的下方，用竖线 + ▼ 连出，卡片上标注从该上游流出的流失数量（不标"停留"）。底部附图例（→ 正向推进 / ▼ 流失 / 终止 / 下方数字为流出数量）。

## 五、验证要点

1. 【岗位】岗位选择为下拉多选，含「全部岗位」，默认选中全部岗位；停用 / 已删除的岗位不出现。
2. 【岗位】选中多个岗位时合并统计，每个岗位的投递独立计数；同一候选人投多个岗位各计一次。
3. 【岗位】切换岗位选择后，三类统计均按新范围重新统计。
4. 【时间段】时间段选择器位于看板顶部，与岗位选择并排；提供起止日期手动输入（起止相同 = 单日）与周快捷（原生周输入 + 上一周 / 下一周按钮），默认本周；结束日期不早于开始日期（非法范围提示并拒绝请求）。
5. 【时间段】切换时间段后，三类统计（状态卡 / 是否联系上 / 流转图）均按新范围重新统计。
6. 【状态卡】10 个状态卡全部展示，卡片数字 = 所选岗位范围内、所选时间段内进入「已筛选」的投递中当前处于该状态的投递数。
7. 【联系上】环形图仅统计所选岗位范围内、所选时间段内进入「已筛选」且当前处于「沟通中」状态的投递，展示未尝试 / 已联系上 / 未联系上 的占比与绝对数量。
8. 【流转图】节点含 已筛选、沟通中、待面试、已面试、已发offer、待入职、已入职、不合适、取消面试、拒offer、已离职 共 11 个状态。
9. 【流转图】每条流转线数量 = 这批投递中从上一状态流转到下一状态的数量（被回退撤销的流转不算）。
10. 【流转图】节点数量 = 流入该节点的各条线数量之和，「已筛选」= 这批投递总数。
11. 【流转图】所选时间段内没有投递时，各节点数量显示为 0。
