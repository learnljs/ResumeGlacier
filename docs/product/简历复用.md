# 简历复用评估

## 一、需求背景

### 1.1 问题现状

当前系统中，简历（Resume）、岗位（Position）和 AI 评估结果（ScreeningResult）三者耦合紧密：

- 一份简历只能产生一条 AI 评估结果（1:1 关系）
- 跟进记录（FollowUpRecord）直接绑定简历，而非绑定某次具体评估
- 评估条件（学历、年限、专业等）不存在结构化存储，完全依赖 AI 自行判断

这导致以下业务场景无法支撑：

1. **同一份简历评估多个岗位**：候选人可能投递了岗位 A，但岗位 B 后来也有了需求，HR 想从已有简历库中看看有没有适合岗位 B 的人
2. **岗位需求变化后重新评估**：岗位 A 的要求调整了，HR 需要重新筛选之前投递的候选人
3. **跟进与评估绑定**：同一份简历对岗位 A 被标记"不合适"，但可能非常适合岗位 B，不应该因为一条跟进记录就排除了该候选人对其他岗位的可能性

### 1.2 目标

实现**简历复用评估**功能，让 HR 在出现新岗位或某岗位缺人时，能够从已有简历库中重新检索、评估并主动联系潜在匹配的候选人，最大化利用简历人才库资源。

---

## 二、核心概念

### 2.1 三个独立概念

| 概念 | 定义 | 管理内容 |
| --- | --- | --- |
| **简历（Resume）** | 候选人的信息和简历文件 | 简历本身信息、解析状态 |
| **岗位（Position）** | 招聘需求 | 岗位名称、部门、工作介绍、任职要求、权重模型 |
| **评估结果（PositionEvaluation）** | 某份简历对某个岗位的一次 AI 评估 | 评分、知识/技能维度星级、AI 分析、评估条件快照 |

### 2.2 关键关系变化

```
【改造前】
Resume ──1:1── 评估结果 ──1:1── 跟进记录

【改造后】
Resume ──1:N── 评估结果 ──1:1── 跟进记录
                  │
               Position
```

一份简历 → 可以对多个岗位产生多条评估结果。
一条评估结果 → 最多对应一条跟进记录。
同一份简历对同一个岗位只保留最新一次评估。

### 2.3 简历解析结构化数据

为支撑硬性条件筛选，简历解析完成后会将其中的学历、院校、专业、工作年限、英语等级等信息提取为独立字段存储。筛选时直接基于这些字段做精准匹配，不依赖 AI 评估后的标签数据。

## 三、页面设计

### 3.1 导航结构

```
招聘中心
├── 简历列表
├── 已筛选简历（现有页面，逻辑适配新数据模型）
├── 简历复用评估    ← 新增
└── 跟进管理
    ├── 沟通中
    ├── 待面试
    ├── 已面试
    ├── 已录用
    └── 不合适

系统配置
├── AI 模型配置
├── 邮箱配置
├── 岗位管理
└── 简历来源
```

### 3.2 简历复用评估页面（新建）

**页面路径**：招聘中心 → 简历复用评估

**页面结构**：顶部筛选区 + 候选人列表区

#### 3.2.1 筛选区域

```
┌──────────────────────────────────────────────────────────────┐
│ 选择目标岗位：[▼ 请选择岗位]                                   │
│                                                              │
│ 评估条件（本次评估使用，均为选填）：                              │
│                                                              │
│ 最低学历    [▼ 不限]                                          │
│ 院校档次    [▼ 不限]                                          │
│ 专业要求    [                            ]  （逗号分隔）       │
│ 工作年限    [▼ 不限]                                          │
│ 英语等级    [▼ 不限]                                          │
│                                                              │
│ [🔍 刷新候选人列表]                                           │
└──────────────────────────────────────────────────────────────┘
```

- 评估条件均为**选填**，不填表示该维度不限制
- 条件选项：
  - 最低学历：不限 / 专科 / 本科 / 硕士 / 博士
  - 院校档次：不限 / 985/211 / 双一流 / 普通本科
  - 专业要求：文本输入，逗号分隔
  - 最低工作年限：不限 / 1年 / 3年 / 5年 / 10年
  - 英语等级：不限 / 四级 / 六级 / 专四 / 专八 / 雅思 / 托福
- 切换岗位后，评估条件**不自动变更**（每个岗位不带默认评估条件），HR 手动填写当次评估条件

#### 3.2.2 候选人列表

```
┌──────────────────────────────────────────────────────────────────────┐
│ [ ] 全选  |  共 N 位候选人  |  [发起 AI 评估]                            │
├────┬─────────┬────────┬──────────┬────────┬──────┬──────┬──────────┤
│ ☐  │ 候选人   │ 学历    │ 工作年限  │ 专业   │ 知识  │ 技能  │ 初筛得分  │
├────┼─────────┼────────┼──────────┼────────┼──────┼──────┼──────────┤
│ ☐  │ 张三    │ 硕士    │ 5年      │ 计算机  │ ⭐4  │ ⭐5  │   85     │
│    │ 男      │ 复旦    │          │ 科学   │      │      │          │
├────┼─────────┼────────┼──────────┼────────┼──────┼──────┼──────────┤
│ ☐  │ 李四    │ 本科    │ 6年      │ 软件   │ ⭐3  │ ⭐4  │   72     │
│    │ 女      │ 浙大    │          │ 工程   │      │      │          │
├────┼─────────┼────────┼──────────┼────────┼──────┼──────┼──────────┤
│ ☑  │ 王五    │ 硕士    │ 8年      │ 计算机  │ ⭐5  │ ⭐5  │   92     │
│    │ 男      │ 清华    │          │ 科学   │      │      │          │
└────┴─────────┴────────┴──────────┴────────┴──────┴──────┴──────────┘
```

**列表字段说明**：

| 列 | 说明 |
| --- | --- |
| 候选人 | 姓名、性别、联系方式 |
| 学历 | 最高学历 |
| 工作年限 | 总工作年限 |
| 专业 | 专业名称 |
| 知识 | AI 评估的知识维度星级评分（1-5），未评估显示 - |
| 技能 | AI 评估的技能维度星级评分（1-5），未评估显示 - |
| 初筛得分 | AI 评估的综合得分（0-100），基于目标岗位的默认权重模型计算，未评估显示 - |

**候选池生成逻辑**：

1. **部门匹配（默认前置条件）**：仅候选人的投递岗位与目标岗位属于**同一部门**时，才进入候选池。跨部门的简历直接排除。
2. **硬性条件过滤**：逐项比对 HR 填写的评估条件与简历解析存储的结构化字段，任一条件不满足则剔除，不进入候选列表
3. **跟进状态排除**：除"不合适"外，其余跟进状态（沟通中/待面试/已面试/已录用）的候选人不进入候选池
4. **未填条件**：HR 未填的维度不做过滤，视为不限

**交互规则**：

- 点击候选人姓名 → 进入简历详情页

#### 3.2.3 评估流程

```
HR 选择目标岗位
    ↓
设置评估条件（选填）
    ↓
点击"刷新候选人列表"
    ↓
系统后端查询：已解析的简历，限与目标岗位同一部门，排除跟进中的简历（不合适列表的除外），同时按硬性条件过滤
    ↓
展示候选人列表
    ↓
HR 勾选候选人 → 点击"发起 AI 评估"
    ↓
使用目标岗位的默认初筛模型执行 AI 评估
    ↓
评估结果写入评估记录
（同一简历对同一岗位覆盖旧记录）
    ↓
可在"已筛选简历"列表中查看本次评估结果
```

### 3.3 跟进管理改造

跟进记录由绑定简历改为绑定评估结果，前端展示不变（列表中已有"职位"列）。

## 四、业务规则汇总

| # | 规则 | 说明 |
| --- | --- | --- |
| 1 | 同一简历+岗位唯一 | 每次评估默认覆盖该简历对同一岗位的旧记录 |
| 2 | 一份简历可评多个岗位 | 各自独立存储，互不影响 |
| 3 | 跟进状态限制 | 除"不合适"外，其余跟进状态（沟通中/待面试/已面试/已录用）的候选人不进入复用评估池 |
| 4 | 部门默认筛选 | 仅有投递岗位与目标岗位同部门的简历才进入候选池，跨部门直接排除 |
| 5 | 评估条件不存岗位 | 仅存于评估结果快照，当次评估当次填写 |
| 6 | 硬性条件过滤 | 不满足硬性条件的候选人直接剔除，不进入候选列表 |
| 7 | 使用目标岗位初筛模型 | 复用评估用目标岗位的默认初筛模型跑 AI |
| 8 | 跟进绑定评估结果 | 跟进记录关联评估结果，一个评估最多一条跟进 |

## 五、验收标准

### 简历复用评估页面

1. 页面入口：招聘中心 → 简历复用评估，可正常访问
2. 筛选区：岗位下拉选择正常，5 项评估条件均可正常填写
3. 点击"刷新候选人列表"后正确展示候选池（除"不合适"外，其余跟进状态均排除）
4. 跨部门的简历不进入候选池
5. 不满足硬性条件的候选人被正确剔除，列表中均为满足条件的候选人
6. "发起 AI 评估"后异步执行，结果正确写入评估记录
7. 同一简历对同一岗位的评估结果，默认覆盖旧记录

### 跟进管理

1. 跟进记录正确绑定评估结果，列表展示不变

### 业务规则验证

1. 除"不合适"外，其余跟进状态（沟通中/待面试/已面试/已录用）的候选人不出现于复用评估池
2. 评估结果默认覆盖旧记录

## 六、评估条件快照

每次评估时将当次使用的评估条件以结构化 JSON 保存，用于后续回溯。

```json
{
  "positionId": "xxx",
  "minEducation": "本科",
  "schoolTier": "985/211",
  "majors": "计算机科学,软件工程",
  "minWorkYears": 3,
  "englishLevel": "六级"
}
```

所有字段可选，`null` 或不传表示该维度不限制。
