# 评估提示词维护 需求文档

> **核心目标**：把评估简历用的提示词从代码里抽出来，配置到界面上，让 HR 自行维护和调整，不再依赖开发发版；按职位绑定，并提供统一的默认模板供未自定义的职位跟随。

---

## 一、问题背景

### 1.1 现状

当前评估简历时用到的所有提示词都硬编码在代码文件里，HR 想调整评估思路或评分标准时：

- 必须由开发修改代码
- 调整周期长（数天甚至数周）
- 业务反馈不能快速验证

### 1.2 业务痛点

- **调整周期长**：业务上发现当前评估规则有偏差，想调整一下，得提需求、排期、改代码、发版，整个流程要等很久
- **试错成本高**：每次调整都要走完整发版流程，HR 不敢频繁试错
- **多个业务线无法差异化**：当前提示词是全局的，不同职位对评估有不同要求时无法满足
- **历史调整追溯困难**：提示词改过几次、改了什么、改的效果如何，没有历史记录

### 1.3 目标

让 HR 能够在界面上直接维护评估提示词（默认模板 + 各职位的自定义），调整后立即对未来评估生效，并能管理历史版本和快速回滚。职位可通过"跟随默认"避免重复维护，也可独立自定义与默认模板解耦。

---

## 二、需求目标

1. **自助维护**：HR 在界面上可自助调整默认模板和各职位的自定义提示词，无需开发介入
2. **立即生效**：保存后对未来评估立即生效，不影响已生成的评估结果
3. **统一基线 + 差异化**：所有职位默认使用统一的默认模板；单个职位可独立自定义与默认模板解耦
4. **跟随机制**：未自定义的职位自动跟随默认模板最新内容；自定义过的职位维持自身版本
5. **版本管理**：默认模板与各职位提示词每次保存自动生成版本，支持查看历史和回滚
6. **安全可控**：必要的校验和约束，避免 HR 误删关键内容导致评估失效

---

## 三、核心方案

### 1. 提示词从代码抽到界面

把当前硬编码在代码里的评估提示词抽取出来，以可编辑文本的形式配置在数据库中，通过界面让 HR 维护。

**调整范围**（以下内容可由 HR 在界面上配置）：

- 默认模板的完整内容
- 各职位的自定义提示词内容

**不在配置范围**（保持代码内置，避免业务配置失误影响整体流程）：

- 简历提取阶段的提示词（`lib/prompts/extraction.ts`，负责从简历原文提取结构化字段）

### 2. 提示词按职位绑定（1:1）

评估时使用哪份提示词，最终由**该份简历所评估的职位**决定：

- **每个职位有独立的提示词配置记录**，通过 `customizedFlag`（自定义标志）区分两种状态
- **未自定义**：以空指针指向默认模板，评估时取默认模板当前生效版本；默认模板更新后自动跟随
- **已自定义**：保留独立的内容快照，自此与默认模板解耦，评估时取职位自身当前生效版本

```
[评估时]
   │
   ├─ 该职位 customizedFlag = false → 用默认模板当前版本内容
   └─ 该职位 customizedFlag = true  → 用职位自定义当前版本内容
```

**理由**：

- 单一中间层更可控，避开按族、按标签等抽象带来的认知成本
- "未自定义即跟随"是单一规则的语义，调试、回滚、追溯都最直接

### 3. 默认模板

默认模板是一份**全局共用的提示词**，初始内容来自代码里当前的硬编码版本。

- **单一可编辑实体**：界面上只有一个默认模板编辑卡
- **未自定义的职位自动跟随**：默认模板更新后，所有未自定义职位对未来评估立即使用新版本，无需分别调整
- **共享同一套版本管理**：默认模板和单职位提示词共用同一套版本机制（详见第 4 节）

### 4. 单一文本编辑

默认模板和每个职位的自定义提示词都是一个**完整的 Markdown 文本**，HR 在编辑器里直接编辑整段内容，无需分段。

理由：

- 业务上提示词是一个整体，人为分段反而割裂了语义
- HR 维护起来更直观：看到一个完整的"评估说明书"概念
- 减少段落校验、必填、关键字校验等复杂规则

### 5. 版本管理

每次保存自动生成一个新版本，保留历史记录。**默认模板和单职位自定义提示词共用同一套版本机制**。

**版本信息**：

- 版本号（各自作用域内从 1 起递增：默认模板 vN、单职位 vN，互不影响）
- 保存时间
- 保存人
- 修改说明（保存时可填写，简要说明本次改了什么）
- 内容快照（完整 Markdown 文本）

**版本能力**：

- 查看历史版本列表
- 查看任意历史版本的完整内容
- 一键回滚到任意历史版本（回滚操作也作为一次新保存记录）
- 对比两个版本之间的差异（高亮新增 / 删除 / 修改的内容）

**版本保留**：保留最近 30 个版本，超过 30 个时最早的版本自动归档（不删除，但折叠显示）。

### 6. 预览功能

**什么是预览**

预览是 HR 在调整提示词的过程中，用**当前编辑器内未保存的内容**临时调一次 AI，看 AI 实际怎么打分、怎么写评语，便于判断调整是否合理。

预览不影响任何业务数据：不会写入候选人评估记录，不修改当前生效版本，不会污染线上数据。HR 可以反复预览多次来调试提示词，直到满意后再保存。

**预览 vs 正式评估**

| 对比项 | 预览 | 正式评估 |
|--------|------|----------|
| 触发人 | HR 手动触发（点"预览"按钮）| 系统自动（候选人投递简历后）|
| 使用的提示词 | 编辑器内**未保存**的最新内容 | 当前**已保存生效**的版本 |
| 数据影响 | 不影响任何业务数据，不修改候选人评估记录 | 会写入候选人评估结果，HR 在列表/详情页可看到 |
| 多次执行 | HR 可反复多次（调试用）| 每份简历通常评估一次 |

**业务流程**：

```
HR 调完提示词
    ↓
点击"预览"按钮
    ↓
弹出预览面板 / 区域
    ↓
HR 选择一份简历作为测试样本
（上传新简历 或 从系统已有简历中选择）
    ↓
HR 点击"开始预览"
    ↓
系统用编辑器内【未保存】的提示词 + 这份简历 → 调 AI
    ↓
返回 AI 的实际输出（评分、评语、维度得分等）
    ↓
HR 判断结果：
├─ 满意 → 关闭预览 → 返回主编辑器 → 点"保存为新版本"（生成新版本，生效）
└─ 不满意 → 继续调整提示词 → 重新预览
```

**预览的价值**：

- **所见即所得**：调完提示词马上看到效果，不用"先保存再看新结果"
- **试错零成本**：调错了不用保存，不会污染线上版本
- **对比方便**：改一段 → 预览 → 不满意 → 再改 → 再预览 → 满意后再保存

### 7. 校验与保护

为避免 HR 误删关键内容导致评估失效，保存时做必要的校验：

- **必填校验**：整段提示词不能为空（必须有实际内容）
- **保存提示**：保存时明确告知影响范围
  - 默认模板保存时："所有未自定义的职位（共 N 个）将使用新版本"
  - 单职位提示词保存时："该职位使用自定义版本，不再跟随默认模板"
- **写前引导（提示句式片段）**：编辑器附带"推荐写法"片段，引导 HR 按既定结构表达，如"对 31 个核心问题逐一回答 是/否"、"答是时引用简历原文作为 evidence"等。该片段降低 HR 写成下游无法解析结构的概率。
- **保存路径 schema 校验（兜底）**：保存前用当前未保存提示词 + 一份样例简历**真实调一次 AI**，将输出与下游期望的 schema 对齐校验。校验规则如下：
  - 顶层必须含 `jdFocus`、`knowledge`（对象，且包含 Q1~Q15 全 15 个 key）、`skill`（对象，且包含 Q16~Q31 全 16 个 key）、`projectType`、`summary`、`strengths`、`weaknesses`，可选 `extracted_tags`
  - 每个 Q 答案的 `answer` 字段必须为 `boolean` 类型
  - 每个 Q 答案的 `evidence` 字段必须为字符串或 `null`
  - 校验失败则禁止保存并把缺漏项、类型不符项以友好提示展示给 HR
  - 代价：每次保存多一次 AI 推理（2 秒级），换取"按保存按钮的瞬间就能确认提示词能被系统吃下"
  - 与解析器、数据库 schema 三者必须保持同步演进；未来若需新增/删除题目或字段，需开发同步调整 ①提示词引导句式 ②校验规则 ③解析器 ④数据库 schema 四者
- **人工豁免**：HR 自认为校验误判时可勾"忽略本次校验强制保存"，但豁免会记录到日志，作为审计追溯。
- **校验失败体验**：保存按钮转圈结束后，若校验失败：
  - 不写入数据库、不创建版本号
  - 编辑器脏状态保留（HR 的修改不丢失），可即时调整后再次点击"保存为新版本"重新校验
  - 失败原因以友好提示展示，列出具体哪些字段缺/类型不符（而不是仅"校验失败"）
  - 若前端报错与 HR 预期不符、且 HR 主动点击"豁免本次校验"，走日志记录后强制保存

注：不做关键字校验和分段落格式校验，HR 可以自由调整提示词的语义结构，技术上不做硬性约束。但下有 schema 校验兜底，上有写前引导降低出错概率。

## 四、业务规则

### 1. 配置位置与入口

- **配置入口**：系统配置 → 提示词管理（独立页面）
- **访问权限**：仅具备"系统配置"权限的 HR 可访问编辑器（与现有职位管理权限一致）
- **职责分布**：
  - 提示词管理页：编辑默认模板、各职位自定义提示词，查看版本与回滚
  - 职位详情页：仅展示当前职位的"提示词状态"（跟随默认 / 已自定义 + 当前版本号），提供"前往提示词管理"跳转入口，不可在职位详情页直接编辑提示词

**与"职位描述 / 筛选要求"的边界**：

评估提示词与职位详情页中的"职位描述"、"筛选要求"是两个独立的维度，修改入口与影响范围互不相关，HR 应理解清楚：

| 维度 | 编辑入口 | 控制粒度 | 控制的内容 |
|------|---------|---------|-----------|
| **评估提示词** | 提示词管理页 | 默认模板 / 各职位 | AI 怎么读 JD、怎么打分、怎么输出（角色定位、评分细则、输出格式约束）|
| **职位描述** | 职位详情页 | 当前职位 | 评估时拼到 prompt 里的"JD 内容"之一 |
| **筛选要求** | 职位详情页 | 当前职位 | 评估时拼到 prompt 里的"JD 内容"之一 |

**两件事互不耦合**：HR 改"评估提示词"不会动职位描述、筛选要求；反过来，改职位描述/筛选要求也不需要碰评估提示词。两边各自保存即可对未来评估立即生效。

### 2. 数据模型（存储快照）

| 实体 | 字段 | 说明 |
|------|------|------|
| **DefaultPrompt** | 单条记录 | 默认模板当前生效内容与版本号 |
| **DefaultPromptVersion** | 版本号、保存时间、保存人、修改说明、内容快照 | 默认模板历史 |
| **PositionPrompt** | `positionId`、`customizedFlag`（boolean）、当前生效版本号 | 每个职位一条，标识是否已脱离默认模板 |
| **PositionPromptVersion** | `positionId`、版本号、保存时间、保存人、修改说明、内容快照 | 单职位自定义历史 |

**继承语义**：

- 评估时读取职位对应的 `PositionPrompt`：
  - `customizedFlag = false` → 使用 `DefaultPrompt` 当前生效内容
  - `customizedFlag = true`  → 使用该职位的 `PositionPrompt` 当前生效版本

### 3. 编辑与保存

- **编辑方式**：默认模板与每个职位一个大文本框，编辑整段 Markdown 内容
- **生效机制**：保存后对未来评估立即生效，不影响已生成的评估结果
- **保存要求**：整段提示词不能为空
- **影响范围**：保存时明确告知
  - 默认模板："所有未自定义的职位（共 N 个）将使用新版本"
  - 单职位提示词："该职位使用自定义版本，不再跟随默认模板"

### 4. 新职位与初始状态

- **新建职位**：自动创建 `PositionPrompt` 记录，`customizedFlag = false`，即"空指针 → 跟随默认模板"
- **HR 主动自定义**：在提示词管理页对某职位点击"自定义"后，从默认模板当前内容拷贝一份作为该职位的 v1，`customizedFlag` 变更为 `true`
  - 自定义切换是一次显式的"分叉"动作，分叉后该职位与默认模板独立演化
- **从自定义恢复为跟随**：将 `customizedFlag` 改回 `false` 即可重新跟随最新默认模板，被替换掉的自定义历史仍然保留作为只读存档（可查看、可回滚到该存档内的任意历史版本以查看当时的内容，但不可作为后续"自定义"动作的起点复用）。
- **恢复后再"自定义"**：在该状态下再次点击"自定义为独立版本"时，**始终**从默认模板的当前最新内容拷贝一份作为该职位的新 v1，不复用上次的历史版本——路径唯一、避免状态混淆

### 5. 版本管理

- **版本生成**：每次保存自动生成一个新版本
- **版本保留**：保留最近 30 个版本，超过 30 个时最早的版本自动归档（不删除，但折叠显示）
- **版本查看**：可在版本历史中查看任意版本的完整内容
- **版本回滚**：支持一键回滚到任意历史版本，回滚操作也作为一次新保存记录
- **版本对比**：支持对比任意两个版本的差异（高亮新增 / 删除 / 修改的内容）

### 6. 评估拼接逻辑

评估一次简历时，AI 提示词完全由**该职位的当前生效版本**决定：

```
模板内容（直接由版本机制提供）：
  - 若该职位 customizedFlag = false → DefaultPrompt 当前生效版本
  - 若该职位 customizedFlag = true  → PositionPrompt 当前生效版本
```

剥离范围限定在评估阶段；提取阶段提示词仍由代码内置，不归本需求管。

### 7. 预览

- **预览入口**：默认模板卡与各职位卡内的"预览"按钮
- **示例简历**：HR 可上传新简历或从已存在的简历中选择一份作为预览样本
- **预览调用**：使用编辑器内当前未保存的提示词调用 AI，返回评估结果
- **预览限制**：预览不影响任何业务数据

### 8. 安全性

- **保存日志**：所有保存操作记录到日志（保存人、时间、修改说明、影响版本）
- **回滚记录**：回滚操作同样记录到日志，可追溯

### 9. 兼容性

- 现有数据（代码内置的提示词）能完整迁移到界面配置中：初始化为 `DefaultPrompt` 的当前内容，所有现存职位的 `customizedFlag` 初始化为 `false`，自动跟随
- 现有评估结果不受影响
- 提示词调整只对未来评估生效，已生成的评估结果不变

## 五、页面交互

提示词管理是**独立的页面**，与职位管理解耦。

**入口位置**：系统配置 → 提示词管理

**页面布局**：

页面采用"顶部默认模板 + 中部职位列表"的纵向布局：

```

│ │ 当前版本：v3                                  │ │
│ │ ┌──────────────────────────────────────────┐ │ │

│ │ │ 请根据以下标准评估候选人的简历...        │ │ │
```

**核心元素**：

- **顶部默认模板卡**：整个系统唯一的默认模板编辑卡
- **中部职位列表**：按职位纵向排列，每职位一份可展开/折叠的编辑卡

  - **已自定义**状态的职位：完整编辑器 + "恢复为跟随默认" 按钮
- **每卡一个编辑器**：默认模板与每个职位的自定义提示词独立编辑，互不干扰
- **当前版本号**：卡片顶部展示当前生效版本号
- **预览**：编辑卡片内的"预览"按钮，基于当前编辑器内未保存内容调 AI 看实际输出

## 六、验收标准

### 1. 自助维护

- HR 在提示词管理页可对默认模板与每个职位的提示词进行查看、编辑
- HR 可在编辑器内自由调整整段提示词内容（Markdown）
- 保存后无需发版即对未来评估生效

### 2. 默认模板与职位自定义

- 默认模板独立可编辑，编辑后所有未自定义的职位自动跟随
- 单职位可独立自定义，自定义后该职位与默认模板解耦，评估时使用职位自身版本
- 单职位可恢复为跟随默认模板，恢复后使用最新默认模板，自身历史不丢失（仅作为存档可查看）
- 切换状态时（跟随 ↔ 自定义）有明确提示

### 3. 单一文本编辑

- 默认模板与每个职位对应一个 Markdown 编辑器，整段编辑
- 不做分段落处理，HR 自由组织内容
- 保存时整段保存

### 4. 版本管理

- 默认模板与单职位提示词每次保存自动生成新版本（在各自作用域内递增）
- 版本列表展示版本号、保存时间、保存人、修改说明
- 支持查看任意历史版本的完整内容
- 支持一键回滚到任意历史版本
- 支持对比任意两个版本的差异
- 保留最近 30 个版本，更早的自动归档

### 5. 预览

- 默认模板与各职位编辑器内提供预览功能
- HR 可上传或选择示例简历
- 系统使用当前未保存的提示词调用 AI，返回实际输出
- 预览不影响任何业务数据

### 6. 校验与安全

- 整段提示词不能为空，否则禁止保存并提示
- 保存时明确告知影响范围（默认模板：N 个未自定义职位受影响；单职位：该职位脱离默认模板）
- 所有保存与回滚操作都有日志记录

### 7. 兼容性

- 现有硬编码的提示词能完整迁移到默认模板
- 现有职位的 `customizedFlag` 默认初始化为 `false`，自动跟随默认模板
- 现有评估结果不受影响
- 提示词调整只对未来评估生效，已生成的评估结果不变

### 8. 入口职责

- 提示词管理页：唯一的提示词编辑入口（默认模板 + 各职位提示词）
- 职位详情页：仅展示"提示词状态"块（只读） + 跳转链接，不可在职位详情页直接编辑
