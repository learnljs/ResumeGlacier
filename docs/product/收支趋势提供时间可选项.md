# 收取趋势图表 · 时间范围选项扩展

## 1. 概要

当前「收取趋势」图表右上角提供「每日 / 每周 / 每月」三种统计粒度的切换，但每个粒度下仅有一种默认时间范围（每日→近一周、每周→近 4 周、每月→近 3 个月），无法满足 HR 对中长期简历收取趋势的查看需求。本 PRD 提出在每个统计粒度下增加可切换的时间范围选项（包括「全部」），让用户在同一图表内即可看到不同长度的时间窗口。

## 2. 背景

「收取趋势」这张图表放在 Dashboard 上，右上角有一个「每日 / 每周 / 每月」的粒度切换器，但每个粒度对应的查看窗口是写死的：每日只能看最近 7 天、每周只能看最近 4 周、每月只能看最近 3 个月，下面也没有任何时间范围选择器。这种「粒度 ↔ 时间长度」绑死的设计在日常使用中带来了明显的别扭—— HR 想看最近一个月的日级走势时，必须先切到「每周」粒度，可一旦切过去，日级别的起伏就看不到了；想看更长时间的整体走势，没有「全部」可选。简单说，痛点本质上是「统计维度」和「时间长度」两个变量被强行耦合，用户根本没法在同一张图里既选粒度又选窗口。

## 3. 目标

**Goals（目标）**

1. 让用户在同一统计粒度下可自由切换多种时间范围，覆盖「短期 → 长期 → 全量」连续场景
2. 用户切换粒度（每日 / 每周 / 每月）时，时间范围自动回到该粒度的默认值
3. 不破坏现有接口与图表的查询性能

**Key Results（衡量指标）**

- 用户在「收取趋势」图表里能找到「想要的那段时间窗口」，不用为了看时间切粒度、不用导数据

## 4. 用户与场景

**目标用户**

简历筛选系统里负责日常招聘收取巡检、阶段性复盘招聘节奏的 HR 。

**约束**

- 移动端图表宽度有限，时间范围选项过多会撑爆控件，需要支持折叠（如「更多」）
- 时间范围选项要兼顾「有意义」与「不至于太长导致图表不可读」，超过一定长度考虑提示用户切换粒度

## 5. 价值主张

| 客户任务 | 本次带来的收益 | 替代方案的不足 |
| --- | --- | --- |
| 不同时间尺度下看同一个指标的趋势 | 同一卡片内一键切换，不用跳出 | 切粒度时数据窗口被强制变化，要重新看 |
| 看长周期趋势 | 提供「全部」选项，无需导数据 | 只能导出 Excel 再画图，效率低 |
| 汇报给老板看不同时间窗 | 切换粒度时保留上一次选择 | 每次都要手动记/重新选 |

差异化：**粒度与时间范围解耦**，用户拥有完整的「统计维度 × 时间长度」二维控制权。

## 6. 解决方案

图表头部布局示意（参考现状图右侧切换器位置）：

```
┌──────────────────────────────────────────────────────────┐
│ 收取趋势                          [每日 ▾]  时间: [近一周 ▾] │
└──────────────────────────────────────────────────────────┘
```

**粒度切换器**：保留现有「每日 / 每周 / 每月」，位置不变。

**时间范围选择器**：新增到粒度切换器**右侧**，形态是下拉选择（Select），标签为「时间：」。

**每个粒度下的时间范围选项（★ 为该粒度默认值）**

| 粒度 | 选项 |
| --- | --- |
| 每日 | 近一周 ★ / 近三周 / 近一个月 / 全部 |
| 每周 | 近 4 周 ★ / 近 8 周 / 近 12 周 / 全部 |
| 每月 | 近 3 个月 ★ / 近 6 个月 / 近 12 个月 / 全部 |

**交互行为**

- 同一粒度下切换时间范围 → 立即重新请求并刷新图表
- 切换粒度 → 时间范围自动跳回该粒度的 ★ 默认值（不记忆上次，刷新页面也回到默认）
- 当前组合显示在图表副标题或 hover tooltip 中（例：「每日 · 近一个月」）
- 移动端放不下时，时间范围下拉框折到第二行
- 选项命名使用相对量（近一周、全部），不显示绝对日期

**边界态**

- 时间范围内无任何数据 → 图表区显示「暂无数据」占位
- 数据点不足 2 个（无法成线）时 → 提示「数据点不足，请切换更短时间范围或更小粒度」
