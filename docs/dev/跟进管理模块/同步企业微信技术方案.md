# 跟进管理数据同步至企微智能表格 — 技术方案

## 一、需求背景

将 HR 系统跟进管理数据自动同步到企业微信智能表格，通过企微「接收外部数据」Webhook 能力实现。单向同步（HR → 企微），候选人进入「待面试」及之后阶段触发，一条投递仅对应一条企微记录。

**关键约束**：字段映射必须配置化，不允许硬编码字段 ID/名称/枚举值。

### 企微 Webhook 协议要点

- URL 格式：`https://qyapi.weixin.qq.com/cgi-bin/wedoc/smartsheet/webhook?key=...`
- 鉴权：URL 中的 `key` 参数，无额外认证
- 新增：`{"add_records":[{"values":{"字段ID":[{...}]}}]}`，返回 `record_id`
- 更新：`{"update_records":[{"record_id":"...","values":{...}}]}`
- 频率限制：单工作表 ≤3000 条/分钟，单文档 ≤10000 条/分钟
- 参考文档：
  - [接收外部数据概述](https://developer.work.weixin.qq.com/document/path/101239)
  - [添加记录](https://developer.work.weixin.qq.com/document/path/101240)
  - [更新记录](https://developer.work.weixin.qq.com/document/path/101241)

## 二、技术方案概要

### 架构

```
PATCH /api/follow-up/records/[id]
  → 现有状态变更逻辑（不变）
  → 同步触发判断 → WeComSyncQueue.enqueue()
  → 返回响应（不阻塞）

WeComSyncQueue（globalThis 单例，异步消费）
  → 聚合窗口（50条 或 5秒）批量推送
  → 字段映射引擎翻译 HR 数据 → 企微格式
  → POST Webhook
  → 成功：更新 wecomRecordId + syncStatus
  → 失败：指数退避重试（最多3次），标记 SYNC_FAILED，写日志

定时扫描（scheduler，每天 02:00）
  → 扫描当日到期记录 → 状态生效 → 走同一队列推送
```

### 触发判断

- 跟进记录状态为 `CONTACTING`（沟通中）→ 不触发
- 状态为 `UNSUITABLE`（不合适）且从未同步过（无 `wecomRecordId`）且来源非已面试 → 不触发（沟通中直接标记不合适，未进入待面试及之后阶段）
- 进入 `INTERVIEW_SCHEDULED`（待面试）且 `wecomRecordId` 为空 → 首次新增
- 状态变更或任意字段修改（备注、面试时间、入职时间、薪资范围、岗位级别等）→ 走更新
- 同步内容：每次触发时，遍历所有启用的 WeComFieldMapping，全量推送当前值

### 5 种转换方式

| transformType | 逻辑 | transformConfig 示例 |
|--------------|------|---------------------|
| DIRECT | 直接取 HR 字段值 | 不需要 |
| ENUM_MAP | 查字典翻译 | `{"INTERVIEW_SCHEDULED":"待面试","HIRED":"已录用"}` |
| TIMESTAMP | 转时间格式 | 不需要 |
| CONCAT | 从 transformConfig 模板解析 `{字段路径}` 变量，分别取值后拼接 | `"{resume.name} - {position.name}"`（hrField 留空） |
| FIXED | 固定值 | `"HR系统"` |

## 三、数据模型

### 新表：WeComFieldMapping

| 字段 | 类型 | 说明 |
|------|------|------|
| id | String (cuid) | 主键 |
| configKey | String | 配置分组 key（默认 `"default"`） |
| hrField | String | HR 字段路径（如 `resume.name`）；特殊值 `"__webhook_url__"` 表示该行为 Webhook URL 配置 |
| wecomFieldId | String | 企微字段 ID（如 `fld_xxx`）；Webhook URL 行留空 |
| wecomFieldName | String | 企微字段标题（展示用） |
| wecomFieldType | String | TEXT / NUMBER / SINGLE_SELECT / DATE_TIME / USER / REFERENCE 等 |
| transformType | String | DIRECT / ENUM_MAP / TIMESTAMP / CONCAT / FIXED |
| transformConfig | String? | JSON，随 transformType 不同存不同内容；Webhook URL 行存 URL 字符串 |
| isEnabled | Boolean | 是否启用（默认 true） |

### 现有表变更：FollowUpRecord 新增 3 个字段

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| wecomRecordId | String? | null | 企微 record_id，更新凭据 |
| wecomSyncStatus | String | `NOT_SYNCED` | NOT_SYNCED / SYNCED / SYNC_FAILED |
| wecomLastSyncedAt | DateTime? | null | 最近同步成功时间 |

### 全局配置

Webhook URL 作为一条特殊的 WeComFieldMapping 记录存储：`hrField = "__webhook_url__"`，`transformConfig` 存 URL。字段映射通过 `configKey` 分组（默认 `"default"`），同一组映射共用一个 Webhook URL。

限流参数、批量条数等通过环境变量管理（`.env`），提供默认值。

## 四、同步流程

### 队列实现

- 复刻 `lib/services/resume-parsing-queue.ts` 的 `globalThis` 单例模式
- 文件：`lib/services/wecom-sync-queue.ts`
- API：`POST /api/wecom/sync`（手动触发重试）
- 聚合策略：50 条一批 或 5 秒超时

### 字段映射引擎

- 文件：`lib/services/wecom-field-mapper.ts`
- 核心函数：`translateRecord(followUpRecord, mappings) → {values}`
- 根据每个 mapping 的 `transformType` 执行转换
- 根据 `wecomFieldType` 决定输出格式：
  - Text → 直接字符串
  - SingleSelect → `[{"text":"..."}]`
  - DateTime → `"yyyy-mm-dd hh:mm:ss"` 或毫秒时间戳字符串
  - Number → 数值
  - Checkbox → 布尔值
- 转换失败/枚举未命中 → 该字段留空，记录告警日志

### 推送失败处理

- HTTP 5xx / 网络错误 → 指数退避重试，最多 3 次
- HTTP 4xx → 不重试，记录日志
- 仍失败 → `wecomSyncStatus = SYNC_FAILED`
- 写入 `data/logs/wecom-sync-YYYY-MM-DD.log`

## 五、配置页面

位置：`/resume/system-config/wecom-sync`，在 `system-config/layout.tsx` 新增 tab。

### 上半部分：Webhook 配置

- URL 输入框 + [测试连接]按钮（发一条含测试文本字段的 add_records 请求，检查 `errcode` 是否为 0）
- 限流参数、批量条数（默认值可覆盖）

### 下半部分：字段映射列表

表格：HR 系统字段 → 转换方式 → 转换参数 → 企微字段 → 操作

- **[导入示例 JSON]**：粘贴企微示例数据，解析企微字段列表（字段 ID + 名称 + 类型）
- **[AI 智能映射]**：调 AI 推荐映射关系，HR 逐行确认后批量写入
- 每行可编辑（弹窗按 transformType 展示不同表单）

## 六、AI 智能映射

- 复用现有 `AIConfig`，新增 `mapping` purpose
- 输入：企微字段定义（名称+类型+枚举） + HR 字段列表 + 历史映射
- 输出：推荐映射 + 置信度（高/中/低）+ 说明
- HR 确认后生效，历史映射沉淀供后续复用
- HR 模板可用字段列表维护在 `lib/constants/wecom-fields.ts`
- 切换新文档时，AI 用字段名文本相似度匹配历史映射

## 七、定时到期同步

- 在 `scheduler.ts` 新增 cron：每日凌晨 02:00
- 扫描 `FollowUpRecord` 中当日到期的离职记录（`resignedAt = 今天`），HR 侧生效 + 触发同步
- 同一推送链路（队列 + 限流 + 重试）
- 扫描窗口可在配置页调整，可关闭/启用

## 八、前端展示

跟进管理表格行右侧静默小标记：
- ✅ 绿点 + "已同步"，hover 显示上次同步时间
- ❌ 红点 + "同步失败"，hover 显示错误信息 + "点击重新同步"
- ◯ 灰色未同步标记

## 十、验收验证

1. HR 在「沟通中」点击「预约面试」→ 候选人进入待面试，企微表格新增一条记录
2. 候选人状态变更为「已面试」→ 企微表格对应记录状态更新
3. 候选人标记「已离职」→ 企微表格同步更新
4. 离职时间到期当天 → 定时任务自动生效并同步
5. 配置页导入示例 JSON → 正确解析企微字段
6. AI 智能映射 → 返回合理推荐
7. 同步失败 → 跟进管理页显示红色标记 + 错误信息
8. 手动点击「重新同步」→ 成功推送
9. 沟通中阶段 → 不同步
