# S3 — 权重模型管理 详细规格说明

> **优先级**：P1（列表和详情页的数据基础）
>
> **依赖**：S1（数据模型重构）
>
> **目标**：提供权重模型的 CRUD 管理页面和 API，支持 HR 创建、编辑、删除权重模型。

---

## 一、功能模块定义

S3 包含以下 3 个模块：

| 模块 | 类型 | 说明 |
|------|------|------|
| 权重模型 API | 新建 | 5 个 RESTful 接口（列表、创建、详情、更新、删除） |
| 权重模型管理页面 | 新建 | `/resume/system-config/weight-models` 页面 |
| Tab 导航 | 修改 | 系统配置 Tab 栏新增"权重模型"标签页 |

## 二、详细功能点描述

### 2.1 权重模型 API

#### 2.1.1 接口列表

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/config/weight-models` | 获取所有权重模型列表 |
| POST | `/api/config/weight-models` | 创建新权重模型 |
| GET | `/api/config/weight-models/[id]` | 获取单个权重模型详情 |
| PUT | `/api/config/weight-models/[id]` | 更新权重模型 |
| DELETE | `/api/config/weight-models/[id]` | 删除权重模型 |

#### 2.1.2 GET /api/config/weight-models

**请求参数**（Query）：
- `category`（可选）：按分类筛选，值为 `initial` 或 `iceberg`

**响应格式**：
```json
{
  "models": [
    {
      "id": "cuid",
      "name": "初筛-默认模型",
      "category": "initial",
      "isDefault": true,
      "weights": "{\"knowledge\":50,\"skill\":50}",
      "createdAt": "2024-01-01T00:00:00.000Z",
      "updatedAt": "2024-01-01T00:00:00.000Z"
    }
  ]
}
```

**排序规则**：默认模型排在前面，其余按 `createdAt desc` 排序。

**错误响应**：
```json
{ "error": "错误信息" }
```

#### 2.1.3 POST /api/config/weight-models

**请求体**：
```json
{
  "name": "自定义初筛模型",
  "category": "initial",
  "isDefault": false,
  "weights": "{\"knowledge\":60,\"skill\":40}"
}
```

**字段校验**：
- `name`：必填，非空字符串
- `category`：必填，仅允许 `initial` 或 `iceberg`
- `isDefault`：可选，默认 false
- `weights`：必填，JSON 字符串

**权重校验规则**：
- JSON 解析成功
- 初筛模型（category = initial）：必须包含 `knowledge` 和 `skill` 两个 key
- 冰山模型（category = iceberg）：必须包含 `knowledge`、`skill`、`selfAwareness`、`personality`、`values`、`motivation` 6 个 key
- 所有值必须为正整数
- 所有值之和必须等于 100

**默认模型处理**：
- 如果 `isDefault = true`，先将同 category 下其他模型的 `isDefault` 设为 false

**成功响应**（201）：
```json
{
  "success": true,
  "model": { ... }
}
```

**错误响应**：
- 400：`{ "error": "模型名称不能为空" }`
- 400：`{ "error": "权重总和必须等于100，当前为：95" }`
- 400：`{ "error": "初筛模型必须包含 knowledge 和 skill 维度" }`
- 500：`{ "error": "未知错误" }`

#### 2.1.4 GET /api/config/weight-models/[id]

**路径参数**：`id` — 权重模型 ID

**成功响应**（200）：
```json
{
  "model": {
    "id": "cuid",
    "name": "初筛-默认模型",
    "category": "initial",
    "isDefault": true,
    "weights": "{\"knowledge\":50,\"skill\":50}",
    "createdAt": "...",
    "updatedAt": "..."
  }
}
```

**错误响应**：
- 404：`{ "error": "权重模型不存在" }`

#### 2.1.5 PUT /api/config/weight-models/[id]

**路径参数**：`id` — 权重模型 ID

**请求体**（均可选，只传需要修改的字段）：
```json
{
  "name": "修改后的名称",
  "weights": "{\"knowledge\":55,\"skill\":45}",
  "isDefault": true
}
```

**校验规则**：
- 如果传了 `weights`，执行与 POST 相同的权重校验
- 如果传了 `isDefault = true`，先将同 category 下其他模型的 `isDefault` 设为 false
- 默认模型的 `category` 不允许修改（通过 weights 结构隐式约束）

**成功响应**（200）：
```json
{
  "success": true,
  "model": { ... }
}
```

**错误响应**：
- 404：`{ "error": "权重模型不存在" }`
- 400：权重校验失败

#### 2.1.6 DELETE /api/config/weight-models/[id]

**路径参数**：`id` — 权重模型 ID

**业务规则**：
- 默认模型（`isDefault = true`）不可删除，返回 400 错误

**成功响应**（200）：
```json
{ "success": true }
```

**错误响应**：
- 404：`{ "error": "权重模型不存在" }`
- 400：`{ "error": "默认权重模型不可删除" }`

#### 2.2.3 功能点

**F3.2.1 — 模型列表展示**
- 显示所有权重模型，按默认优先 + 创建时间倒序排列
- 每个模型卡片显示：名称、分类标签、维度权重明细、是否默认、创建时间
- 默认模型显示"默认"徽章（Badge 组件）
- 空状态时显示引导信息

**F3.2.2 — 新增模型**
- 点击"新增模型"按钮，展开内联表单
- 表单字段：
  - 模型名称：文本输入框，必填
  - 模型分类：单选按钮组（初筛模型 / 冰山模型），必填
  - 维度权重：根据选择的分类动态显示
    - 初筛模型：知识、技能（2 个输入框）
    - 冰山模型：知识、技能、自我认知、品质特质、价值观、动机（6 个输入框）
  - 权重总和：实时计算显示，等于 100 时显示 ✅，不等于时显示 ❌ 和当前值
- 保存按钮：权重总和 ≠ 100 时禁用
- 取消按钮：折叠表单，清空输入

**F3.2.3 — 编辑模型**
- 点击模型卡片的"编辑"按钮，展开内联表单（预填现有数据）
- 分类不可修改（灰色禁用状态）
- 维度根据分类自动显示
- 权重输入框预填现有值
- 保存时执行与新增相同的校验

**F3.2.4 — 删除模型**
- 点击模型卡片的"删除"按钮
- 弹出确认对话框："确定要删除权重模型「{name}」吗？删除后无法恢复。"
- 确认后调用 DELETE API
- 默认模型的"删除"按钮禁用，tooltip 提示"默认权重模型不可删除"
- 删除成功后刷新列表

**F3.2.5 — 分类选择联动**
- 选择"初筛模型"时：
  - 维度区域显示 2 个输入框：知识、技能
  - 每个输入框 placeholder 为 "0"
- 选择"冰山模型"时：
  - 维度区域显示 6 个输入框：知识、技能、自我认知、品质特质、价值观、动机
  - 每个输入框 placeholder 为 "0"
- 切换分类时清空已输入的权重值

**F3.2.6 — 权重总和校验**
- 每次输入框值变化时实时计算总和
- 总和显示在表单底部：
  - 等于 100：显示绿色 "权重总和: 100 ✅"
  - 不等于 100：显示红色 "权重总和: {当前值} ❌（必须等于100）"
- 保存按钮在总和 ≠ 100 时 disabled

## 三、用户交互流程

### 3.1 创建权重模型流程

```
用户点击"新增模型"
  → 展开内联表单
  → 输入模型名称
  → 选择模型分类（初筛模型/冰山模型）
  → 维度输入框根据分类自动显示
  → 逐个输入各维度权重值
  → 实时查看权重总和
  → 总和 = 100 时，"保存"按钮启用
  → 点击"保存"
  → 前端校验通过 → 调用 POST /api/config/weight-models
  → 成功 → toast 提示"权重模型创建成功"，刷新列表，折叠表单
  → 失败 → toast 提示错误信息
```

### 3.2 编辑权重模型流程

```
用户点击模型卡片的"编辑"按钮
  → 展开内联表单（预填现有数据）
  → 修改权重值
  → 实时查看权重总和
  → 点击"保存"
  → 调用 PUT /api/config/weight-models/[id]
  → 成功 → toast 提示"权重模型更新成功"，刷新列表
  → 失败 → toast 提示错误信息
```

### 3.3 删除权重模型流程

```
用户点击模型卡片的"删除"按钮
  → 弹出确认对话框
  → 点击"确定"
  → 调用 DELETE /api/config/weight-models/[id]
  → 成功 → toast 提示"权重模型已删除"，刷新列表
  → 失败 → toast 提示错误信息（如"默认权重模型不可删除"）
```

## 五、业务规则汇总

| 编号 | 规则 | 实现位置 |
|------|------|---------|
| BR3.1 | 同一 category 下只能有一个默认模型 | API: POST/PUT 处理 |
| BR3.2 | 权重总和必须等于 100 | 前端校验 + API 校验 |
| BR3.3 | 权重值必须为正整数 | 前端校验 + API 校验 |
| BR3.4 | 初筛模型必须包含 knowledge、skill | API 校验 |
| BR3.5 | 冰山模型必须包含全部 6 个维度 | API 校验 |
| BR3.6 | 默认模型不可删除 | API 校验 + 前端按钮禁用 |
| BR3.7 | 编辑时分类不可修改 | 前端禁用分类选择 |
| BR3.8 | 切换分类时清空权重值 | 前端联动逻辑 |

## 六、非功能需求

### 6.1 性能要求

- 模型列表加载时间 < 500ms
- 保存操作响应时间 < 1s
- 权重总和实时计算无延迟

### 6.2 UI/UX 要求

- 使用项目统一的 UI 组件（`@/components/ui/*`）
- 使用 `sonner` toast 显示操作结果
- 使用 `lucide-react` 图标（建议：`Scale` 或 `Weight` 图标用于侧边栏）
- 表单校验即时反馈，不等待提交
- 响应式布局，适配不同屏幕宽度

### 6.3 安全性

- 内部系统，无特殊安全要求
- API 校验不可绕过（后端必须校验权重总和）
