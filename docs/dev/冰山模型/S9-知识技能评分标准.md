# S9 - 知识/技能维度评分标准升级

## 一、概述

基于《知识、技能评分标准需求文档》，升级 AI 筛选 prompt，使知识和技能两个维度的评分从简单数字升级为**结构化评分**（含 4 个思考方向的信号提取、简历原文引用、综合推理），提高评分的可解释性和一致性。

### 核心变更

| 变更项 | 旧 | 新 |
|-------|---|---|
| AI 输出格式 | `knowledge: 3`, `skill: 4`（数字） | `knowledge: {rating, aspects, reasoning}`（结构化） |
| 评分依据 | 无 | 4 个思考方向 × 信号 + 简历原文引用 |
| 数据存储 | `EvaluationDimension.rating` + `comment` | `rating` + `comment`（一句话摘要） + `aiDetail`（新增，结构化 JSON） |
| detailAnalysis | 存在 | **直接删除字段**（不设替代，HR 想看整体分析直接看简历） |
| prompt 体积 | ~800 tokens | 有 JD ~2500-3000 tokens，无 JD ~1800-2200 tokens（按需加载） |
| max_tokens | 默认值（2000） | 4000 |
| Token 成本 | 基准 | 输入 +3x，输出 +2x（按需加载策略缓解） |

## 二、数据模型变更

### 2.1 EvaluationDimension 新增字段

```prisma
model EvaluationDimension {
  // ... 现有字段不变
  aiDetail    String?   // AI 结构化评分依据（JSON）
}
```

**字段说明**：
- `aiDetail`：仅 AI 评分时写入，存储结构化 JSON（仅含 `aspects` + `reasoning`，不含 summary/strengths/weaknesses）。**永不自动清空**——HR 修改评分时，`source` 改为 `manual`，`rating` 更新为 HR 评分，但 `aiDetail` 保留作为 AI 原始评分依据供参考。前端根据 `source` 字段判断展示状态（`source: "manual"` 时显示"HR 已覆盖评分"，仍可展开查看 AI 原始依据）。
- `comment`：AI 评分时自动生成一句话摘要（如"行业认知达标，理论基础扎实"），供雷达图 tooltip 快速预览；HR 手动评分时存 HR 备注（限制 500 字符）。`comment` 与 `aiDetail.reasoning` 粒度不同——`comment` 是一句话概要，`reasoning` 是完整推理过程。

### 2.2 aiDetail JSON 结构

```json
{
  "knowledge": {
    "rating": 3,
    "aspects": {
      "industry": {
        "signal": "有2年互联网行业经验，了解行业基本运作模式",
        "excerpt": "2022-2024 在XX公司从事互联网产品运营工作"
      },
      "theory": {
        "signal": "市场营销专业本科，专业对口",
        "excerpt": "XX大学 市场营销 本科"
      },
      "tools": {
        "signal": "列出数据分析相关工具",
        "excerpt": "熟练使用 Excel、SQL 进行数据分析"
      },
      "learning": {
        "signal": "有自学记录",
        "excerpt": "自学 Python 数据分析相关课程"
      }
    },
    "reasoning": "4个方向中，行业认知、专业理论、工具认知均指向3星，学习积累指向2星，多数方向指向3星，整体评为3星"
  },
  "skill": {
    "rating": 4,
    "aspects": {
      "practice": {
        "signal": "在多个项目中运用专业能力完成数据分析任务",
        "excerpt": "主导用户画像分析项目，完成数据清洗、建模、可视化全流程"
      },
      "toolUse": {
        "signal": "SQL 和 Python 有深度使用场景",
        "excerpt": "使用 Python pandas 处理百万级用户行为数据，产出分析报告"
      },
      "output": {
        "signal": "有明确的业务交付成果",
        "excerpt": "分析结果直接推动产品改版，DAU 提升 15%"
      },
      "judgment": {
        "signal": "有独立分析判断的场景",
        "excerpt": "通过漏斗分析定位注册转化瓶颈，提出优化方案并落地"
      }
    },
    "reasoning": "4个方向均指向4星水平，尤其业务产出有量化数据支撑，整体评为4星"
  },
  "summary": "候选人具备市场营销背景，有2年互联网行业经验，数据分析能力突出...",
  "strengths": ["数据分析实操能力强，有量化业务成果"],
  "weaknesses": ["行业深度认知有待加强，缺乏高级分析工具的使用经验"]
}
```

> **注意**：`summary`、`strengths`、`weaknesses` 是 AI 输出格式中的顶层字段，存储到 `ScreeningResult` 表（与现有逻辑一致）。`aiDetail` 仅存储 `knowledge` 和 `skill` 对象中的 `aspects` + `reasoning` 部分。

### 2.3 各方向含义对照

| 维度 | 方向 key | 知识维度含义 | 技能维度含义 |
|------|---------|------------|------------|
| 1 | `industry` / `practice` | 行业认知 | 专业实操 |
| 2 | `theory` / `toolUse` | 专业理论 | 工具运用 |
| 3 | `tools` / `output` | 工具与方法认知 | 业务产出 |
| 4 | `learning` / `judgment` | 学习积累 | 专业判断 |

新增以下内容到现有系统 prompt：

```
## 知识维度评分标准

### 思考方向
1. 行业认知：对目标行业知道多少
2. 专业理论：专业知识和理论掌握了多少
3. 工具与方法认知：对专业工具和工作方法知道多少
4. 学习积累：知识储备是否有持续扩充

### 1-5 星判定标准

⭐ 1星 — 知识储备明显不足
- 学历专业与岗位要求不相关，且没有任何自学或培训补充
- 简历中没有出现目标行业相关的经验或认知描述
- 没有提到岗位相关的专业工具或方法
- 没有培训、课程、自学或证书考取的记录

⭐⭐ 2星 — 有一定基础，但整体偏弱
- 学历专业大体沾边但深度不足，或非对口专业仅有基础自学
- 简历中提及过目标行业，但仅作为名词出现，缺少实质描述
- 仅提到 1-2 个基础工具名称或方法词汇，没有展开说明
- 表达了学习意愿但缺乏具体的学习行为或证书记录

⭐⭐⭐ 3星 — 达到岗位基线要求
- 学历专业对口（本科层次），或持有岗位相关的初级资格证书；若 JD 学历专业不限则此项不作为评分依据
- 简历中有目标行业的实践经历，出现了行业基本概念或业务术语
- 列出了岗位所需的主流工具或方法，有一定认知描述
- 有具体的学习行为记录，如列出的培训课程、考取的证书等

⭐⭐⭐⭐ 4星 — 知识扎实，有较深积累
- 学历专业对口且来自 985/211/双一流院校/海外院校，或持有行业中高级资格证书，或为相关专业硕士及以上学历；若 JD 明确「学历专业不限」或对学历层次无硬性要求则此项不作为评分依据
- 行业经验年限达到或超过 JD 标注的年限要求，简历描述中体现了对行业运作模式的理解
- 工具与方法论认知面广，或对某些工具有深入认知的描述
- 学习行为有多个时间节点，能看出知识体系的持续扩展

⭐⭐⭐⭐⭐ 5星 — 专家级别，有深度洞察
- 持有行业顶级资格证书，或为相关专业博士学历，或简历中出现学术成果、专利；若 JD 明确「学历专业不限」或对学历层次无硬性要求，则不强制按上述院校/学位/证书要求评分，应更多从行业洞察深度、知识体系完整度、学习轨迹等其他知识信号判断
- 对行业趋势、痛点或竞争格局有分析性的描述，或有行业相关的公开发表物
- 掌握行业全链条工具与方法，有搭建体系或培训他人的知识输出记录
- 学习记录高密度、高质量，且学习成果与工作产出之间有明确关联

## 技能维度评分标准

### 思考方向
1. 专业实操：能否运用专业知识完成实际工作
2. 工具运用：能否熟练使用专业工具完成工作
3. 业务产出：实际交付了什么成果
4. 专业判断：能否在专业领域内独立分析和做判断

### 1-5 星判定标准

⭐ 1星 — 技能水平明显不足
- 简历中没有列出与岗位相关的专业技能，实践经历中也未出现专业技能的使用描述
- 没有专业工具的任何使用提及
- 实践经历中没有任何交付物或成果描述
- 实践描述中看不出需要专业判断的场景

⭐⭐ 2星 — 有基础但整体偏弱
- 列出了 1-2 个专业技能名称，但仅为清单式列举，实践描述中没有使用场景
- 仅提到专业工具名称，没有操作或运用描述
- 实践经历中仅有任务罗列，缺乏明确的交付物或产出描述
- 有专业判断场景但停留在执行层面，不是独立判断

⭐⭐⭐ 3星 — 达到岗位要求，能独立完成专业工作
- 技能清单覆盖了岗位的核心专业要求，且至少部分技能在实践描述中有实际运用（出现了「用什么专业能力做了什么」）
- 专业工具在实践描述中有具体使用场景
- 实践经历中有明确的交付物或完成事项的描述（交代了「做成了什么」）
- 至少有一段实践描述体现了需要运用专业判断的场景

⭐⭐⭐⭐ 4星 — 专业能力扎实，能高质量完成
- 核心专业技能齐全，多项技能在实践描述中有深度运用，成果有明确交付物或量化数字
- 多种专业工具有深度使用描述，部分达到熟练或精通程度
- 实践成果突出，有可量化的业绩或产出的具体数字
- 有多段需要独立做出复杂专业判断的场景描述

⭐⭐⭐⭐⭐ 5星 — 专业领域专家，能创新突破
- 有专业技能创新应用、技术攻坚或专业领域知识输出的描述（如专利、专业文章、系统性培训、行业标准制定参与）
- 专业工具的运用达到了可以对外输出或指导他人的水平
- 有解决系统性、行业级问题的描述，且对业务产生了显著的可量化影响
- 专业判断达到了能够影响业务决策或行业实践的水平

## 通用评分规则
1. 评分集中在 2-4 星。仅当简历信号明显符合 1 星或 5 星的全部典型特征时才给出该评分。
2. 每个星级评定必须引用简历中的具体原文片段作为依据，不能用概括性描述。
3. 知识和技能需独立判定：出现在教育背景、证书、自学板块的内容侧重知识；出现在实践经历中"做了什么、做成了什么"的描述侧重技能。
4. 综合 4 个思考方向的信号：多数方向指向哪一档即为该维度的综合星级。两个星级信号持平取高，但升至 5 星前需验证该星级所有描述均能在简历中找到对应信号。简历本身不要求 4 个方向都覆盖到信号，某个方向简历未提及而其他方向信号集中在 3-4 星时，视为简历的「侧重描述」而非候选人能力缺失，不因此降级。
5. 若简历无正式工作经历（应届生/实习生），课程项目、竞赛作品、个人项目、实习经历中的专业实操描述均作为有效实践经历，与正式工作经历具有同等评分效力。

## JD 程度词映射表
| JD 表述 | 简历最低信号 |
|--------|------------|
| 了解 | 仅出现工具/技能名称即可 |
| 熟悉 | 名称 + 至少1段使用场景 |
| 熟练 | 名称 + 2段及以上不同场景的深度使用 |
| 精通 | 名称 + 指导他人或解决复杂问题 |
| 掌握 | 名称 + 至少1段完整使用场景与产出 |
| 多门 | 同类技术/语言出现 ≥2 个 |
| 一定的 | 至少出现 1 段相关使用描述 |
| 一定的...能力 | 简历中需出现该能力对应的行为或成果描述 |
```

```
## 评分步骤

### 第一步：从 JD 中提取关键信息

- 分别给出信号描述和简历原文引用
```


### 3.5 通用筛选 prompt（buildGenericScreeningUserPrompt）

- 跳过 JD 解析步骤和程度词映射表（无 JD 可对照）
- 保留 4 个思考方向 + 1-5 星判定标准（评分基础，不可省略）
- 保留评分校准规则 + 应届生适配规则
- 保留结构化输出格式
- 在 prompt 中说明：「未提供岗位 JD，请基于通用行业标准评估」

### 3.6 按需加载评分标准策略

为控制 token 消耗，评分标准按需加载：

| 场景 | 加载内容 | 预估 token |
|------|---------|-----------|
| 有 JD（职位匹配成功） | 4 个思考方向 + 1-5 星判定标准 + JD 程度词映射表 + JD 解析步骤 + 评分校准规则 + 应届生适配规则 | ~2500-3000 |
| 无 JD（通用筛选） | 4 个思考方向 + 1-5 星判定标准 + 评分校准规则 + 应届生适配规则（跳过 JD 相关内容） | ~1800-2200 |

实现方式：`knowledge-skill-criteria.ts` 导出两个版本的评分标准常量——完整版（`FULL_CRITERIA`）和精简版（`GENERIC_CRITERIA`），`buildScreeningUserPrompt` 使用完整版，`buildGenericScreeningUserPrompt` 使用精简版。

### 4.3 ai-screener.ts

#### 4.3.1 解析逻辑变更

解析 AI 返回的 JSON，增加容错逻辑：

```typescript
interface ParsedDimension {
  rating: number       // 1-5
  comment: string      // 一句话摘要
  aiDetail: object | null  // 结构化 JSON（aspects + reasoning）
}

function parseScreeningResult(aiResponse: string) {
  const parsed = JSON.parse(aiResponse)

  const knowledge = parseDimension(parsed.knowledge, 'knowledge')
  const skill = parseDimension(parsed.skill, 'skill')

  return {
    knowledge,
    skill,
    summary: parsed.summary || '',
    strengths: Array.isArray(parsed.strengths) ? parsed.strengths.map(String) : [],
    weaknesses: Array.isArray(parsed.weaknesses) ? parsed.weaknesses.map(String) : [],
  }
}

function parseDimension(raw: unknown, dimName: string): ParsedDimension {
  // 兼容旧格式：如果 raw 是数字，直接返回
  if (typeof raw === 'number') {
    return { rating: clampRating(raw), comment: `${dimName === 'knowledge' ? '知识' : '技能'}${clampRating(raw)}星`, aiDetail: null }
  }
  // 新格式：提取 rating、aspects、reasoning
  if (raw && typeof raw === 'object' && 'rating' in raw) {
    const obj = raw as any
    const aspects = obj.aspects || null
    const reasoning = obj.reasoning || ''
    // 生成一句话摘要
    const comment = generateComment(dimName, obj.rating, aspects, reasoning)
    return {
      rating: clampRating(obj.rating),
      comment,
      aiDetail: aspects ? { aspects, reasoning } : null,
    }
  }
  // 解析失败：返回默认值
  return { rating: 0, comment: '解析失败', aiDetail: null }
}

function clampRating(rating: unknown): number {
  const n = Number(rating) || 0
  return Math.max(1, Math.min(5, Math.round(n)))
}

function generateComment(dimName: string, rating: number, aspects: any, reasoning: string): string {
  const label = dimName === 'knowledge' ? '知识' : '技能'
  // 从 reasoning 中提取关键信息作为一句话摘要
  if (reasoning) {
    // 取 reasoning 的前50个字符作为摘要
    const brief = reasoning.length > 50 ? reasoning.slice(0, 50) + '...' : reasoning
    return `${label}${clampRating(rating)}星：${brief}`
  }
  return `${label}${clampRating(rating)}星`
}
```

## 七、容错策略

| 场景 | 处理方式 |
|------|---------|
| AI 返回简单数字（旧格式） | 直接当旧格式处理，`aiDetail` 留空，`comment` 按现有逻辑生成 |
| 某维度 aspects 缺少 1-2 个方向 | 保存已有的，缺失方向显示「AI 未提供」 |
| rating 不在 1-5 范围 | 截断到合法范围 |
| 整个结构化部分解析失败 | 回退到提取简单 rating，`aiDetail` 留空，不阻断筛选 |
| AI 返回的 key 名称不完全匹配 | **名称模糊匹配**：先尝试精确匹配英文 key（industry/theory/tools/learning/practice/toolUse/output/judgment），失败后尝试匹配中文标签（行业认知→industry，专业理论→theory，工具与方法认知→tools，学习积累→learning，专业实操→practice，工具运用→toolUse，业务产出→output，专业判断→judgment），最后兜底返回默认结构 |

**不做迁移**。

- 只对新筛查的简历生成结构化评分
- 不自动重新筛查

## 八（补充）、冰山下层维度状态说明

S9 仅涉及 `knowledge`（知识）和 `skill`（技能）两个维度的 AI 结构化评分。冰山模型下层的 4 个维度在 S9 之后的状态：

| 维度 | key | S9 之后的状态 |
|------|-----|-------------|
| 自我认知 | `selfAwareness` | 纯手动评分，不参与 AI 筛选 |
| 品质特质 | `personality` | 纯手动评分，不参与 AI 筛选 |
| 价值观 | `values` | 纯手动评分，不参与 AI 筛选 |
| 动机 | `motivation` | 纯手动评分，不参与 AI 筛选 |

这 4 个维度需要在面试环节由 HR 手动评分，不在简历筛选阶段通过 AI 评估。后续迭代可能对这些维度引入类似的结构化评分（届时为 S10+）。

## 十、验收标准

1. AI 筛选新简历时，输出的知识和技能评分包含 4 个思考方向的信号、简历原文引用和综合推理
2. 评分依据在简历详情页的评估 Tab 中正确展示，每个维度可展开查看 4 个方向的信号和原文
3. 评分集中在 2-4 星区间，1 星和 5 星仅在信号明显时出现
4. 知识和技能的评分能做出区分：教育背景/证书侧重知识，实践经历侧重技能
5. 应届生/实习生的项目经验、竞赛经历能正常参与评分
6. JD 中的程度词（了解/熟悉/熟练/精通）能正确影响技能评分
7. 旧简历的详情页不受影响，`aiDetail` 为空时只显示星级不显示依据
8. AI 输出格式异常时，系统能降级处理，不阻断筛选流程
9. 通用筛选（无 JD）时，评分基于简历信号的绝对强度，不对照岗位要求，prompt 中不包含 JD 程度词映射表和解析步骤
10. 按需加载策略生效：有 JD 时 prompt 体积约 2500-3000 tokens，无 JD 时约 1800-2200 tokens
11. AI 返回的 key 名称不匹配时，名称模糊匹配能正确识别中文标签并映射到对应维度
12. 冰山下层 4 个维度（自我认知、品质特质、价值观、动机）不受 S9 影响，仍为纯手动评分
