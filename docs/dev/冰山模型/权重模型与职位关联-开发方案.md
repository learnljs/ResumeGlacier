# 权重模型与职位关联 — 开发方案

> 基于需求文档 `权重模型与职位进行关联.md`，经系统技术讨论后制定的详细开发方案。

---

## 一、需求分析与功能拆解

### 1.1 核心目标

将权重模型管理从独立的全局模块改造为**职位内嵌管理**，实现不同职位评分规则的差异化配置，缩短 HR 操作路径。

### 1.2 功能清单

| 编号 | 功能 | 说明 |
|------|------|------|
| F1 | 删除独立权重模型管理页面 | 系统配置导航中移除权重模型 tab，旧路由直接 404 |
| F2 | 职位管理主页重构 | 仅展示"启用中"职位列表 + "新增职位"按钮 + "已停用职位"入口 |
| F3 | 职位编辑独立页面 | 新增和编辑职位均进入独立全屏页面，包含职位基础信息 + 权重模型管理 |
| F4 | 已停用职位子页面 | 展示所有停用职位，置灰显示，提供启用按钮 |
| F5 | 职位内嵌权重模型管理 | 按初筛/冰山两分组，支持 + 按钮新增、编辑、删除、设为默认 |
| F6 | 职位默认模型绑定 | Position 新增 defaultInitialModelId / defaultIcebergModelId 字段 |
| F7 | 新建职位自动初始化模型 | 以系统预置模板创建该职位的初筛和冰山默认模型 |
| F8 | 职位三态管理 | active（启用中）/ disabled（停用），删除为物理操作 |
| F9 | 评分按职位模型计算 | 各列表和详情页评分使用候选人投递职位的默认权重模型 |
| F10 | 简历详情页模型切换 | 可选范围限定为该岗位自身模型列表 |

### 1.3 业务规则

| 规则 | 说明 |
|------|------|
| 模型归属职位 | WeightModel 通过 positionId 外键关联 Position，删除职位时级联删除 |
| 每类仅一个默认 | 每个职位在初筛/冰山下各只有一个默认模型，由 Position 的两个字段唯一确定 |
| 默认模型不可删 | 被 Position 引用的默认模型需先切换才能删除（前后端双重校验） |
| 新建职位模板 | 以常量模板自动初始化两份模型（初筛 + 冰山） |
| 停用锁定 | 停用后职位基础信息和权重模型都不可修改，先启用才能改 |
| 删除条件 | 仅简历数=0 且状态为 active 的职位可物理删除 |
| 评分跟随职位 | 各列表/详情页评分使用候选人投递职位的默认模型计算 |

## 二、系统设计方案

### 2.1 数据模型变更

#### 2.1.1 WeightModel

```prisma
model WeightModel {
  id          String    @id @default(cuid())
  name        String                                          // 模型名称
  category    String                                          // "initial" | "iceberg"
  weights     String                                          // JSON: {"knowledge": 50, "skill": 50, ...}
  positionId  String                                          // ★新增：归属职位
  position    Position  @relation(fields: [positionId], references: [id], onDelete: Cascade)
  createdAt   DateTime  @default(now())
  updatedAt   DateTime  @updatedAt

  @@index([category])
  @@index([positionId])                                       // ★新增
}
```

**变更**：
- 删除 `isDefault Boolean @default(false)` — 默认标记由 Position 字段控制
- 新增 `positionId String` + `position Position` 关系（级联删除）
- 新增 `@@index([positionId])`

#### 2.1.2 Position

```prisma
model Position {
  id                     String                @id @default(cuid())
  title                  String
  department             String?
  description            String
  requirements           String
  keywords               String?
  status                 String                @default("active")  // ★变更：替代 isActive，"active" | "disabled"
  defaultInitialModelId  String?                                     // ★新增：默认初筛模型
  defaultIcebergModelId  String?                                     // ★新增：默认冰山模型
  defaultInitialModel    WeightModel?          @relation("DefaultInitial", fields: [defaultInitialModelId], references: [id])
  defaultIcebergModel    WeightModel?          @relation("DefaultIceberg", fields: [defaultIcebergModelId], references: [id])
  createdAt              DateTime              @default(now())
  updatedAt              DateTime              @updatedAt
  resumes                Resume[]
  weightModels           WeightModel[]                               // ★新增
  evaluationDimensions   EvaluationDimension[]
}
```

**变更**：
- `isActive Boolean` → `status String @default("active")`（active / disabled）
- 新增 `defaultInitialModelId` / `defaultIcebergModelId`（可选，指向 WeightModel）
- 新增 `weightModels` 反向关系
- 新增两命名关系 `DefaultInitial` / `DefaultIceberg`

### 2.2 接口设计

#### 2.2.1 新增接口

| 方法 | 路由 | 说明 |
|------|------|------|
| GET | `/api/positions/[id]/weight-models` | 获取该职位的权重模型列表，可选 `?category=initial\|iceberg` |
| POST | `/api/positions/[id]/weight-models` | 为该职位创建新权重模型 |
| GET | `/api/positions/[id]/weight-models/[modelId]` | 获取单个模型详情 |
| PUT | `/api/positions/[id]/weight-models/[modelId]` | 更新模型（名称、权重） |
| DELETE | `/api/positions/[id]/weight-models/[modelId]` | 删除模型（被 Position 设为默认的不可删） |

#### 2.2.2 改造接口

| 方法 | 路由 | 变更 |
|------|------|------|
| GET | `/api/positions` | 增加 `?status=disabled` 查询已停用职位；加 `_count.resumes` |
| POST | `/api/positions` | 创建后自动以模板初始化两份权重模型并设为默认 |
| PUT | `/api/positions/[id]` | 支持更新 `status`（启用↔停用）、`defaultInitialModelId`、`defaultIcebergModelId`，加模型归属校验 |
| DELETE | `/api/positions/[id]` | 物理删除（仅 status=active 且简历数=0），级联删模型 |

#### 2.2.3 删除接口

| 方法 | 路由 | 原因 |
|------|------|------|
| ALL | `/api/config/weight-models` | 全局模型管理不再存在 |
| ALL | `/api/config/weight-models/[id]` | 同上 |

### 2.3 核心业务逻辑

#### 2.3.1 新建职位自动初始化模型

```
POST /api/positions
  ↓
1. 验证 title、requirements 必填
2. 创建 Position（status="active"）
3. 查常量 DEFAULT_WEIGHT_MODEL_TEMPLATES：
   initial: { name: "初筛-默认模型", weights: { knowledge: 50, skill: 50 } }
   iceberg: { name: "冰山-默认模型", weights: { knowledge: 15, skill: 15, selfAwareness: 20, personality: 20, values: 15, motivation: 15 } }
4. 创建两个 WeightModel（positionId = 新职位 id）
5. 设置 Position.defaultInitialModelId = 初筛模型 id
6. 设置 Position.defaultIcebergModelId = 冰山模型 id
7. 返回完整 Position（含默认模型）
```

#### 2.3.2 设置默认模型

```
入口：PUT /api/positions/[id] { defaultInitialModelId: "xxx" }
  ↓
1. 校验 WeightModel.findById("xxx") 存在
2. 校验 WeightModel.positionId === Position.id（归属校验）
3. 校验 WeightModel.category === "initial"（类别匹配）
4. 更新 Position.defaultInitialModelId = "xxx"
5. 返回更新后的 Position
```

#### 2.3.3 评分计算改造

```
autoCalculateScores(resumeId)
  ↓
1. resume = Resume.findById(resumeId), include position
2. 如果 !resume.positionId → initialScore=null, compositeScore=null, return
3. position = resume.position
4. 如果 position.defaultInitialModelId:
     initialScore = calculateScore(resumeId, position.defaultInitialModelId).totalScore
   否则 initialScore = null
5. 如果 position.defaultIcebergModelId:
     compositeScore = calculateScore(resumeId, position.defaultIcebergModelId).totalScore
   否则 compositeScore = null
6. 更新 Resume.{ initialScore, compositeScore }
```

#### 2.3.4 职位启用/停用

```
PUT /api/positions/[id] { status: "disabled" }
  ↓
1. 校验当前状态不是 disabled
2. 更新 status = "disabled"
3. 返回更新后的 Position

PUT /api/positions/[id] { status: "active" }
  ↓
1. 校验当前状态是 disabled
2. 更新 status = "active"
3. 返回更新后的 Position
```

**规则**：停用状态下，PUT 更新职位信息（title/department/description/requirements/keywords）和 PUT 更新权重模型都应返回 400 错误 "该职位已停用，请先启用后再修改"。前端也通过页面只读来配合。

#### 2.3.5 物理删除职位

```
DELETE /api/positions/[id]
  ↓
1. position = Position.findById(id), include _count.resumes
2. 如果 position.status !== "active" → 400 "只能删除启用中的职位"
3. 如果 position._count.resumes > 0 → 400 "该职位存在 N 条关联简历，不可删除，请先停用"
4. 如果 position._count.resumes === 0：
   prisma.weightModel.deleteMany({ where: { positionId: id } })
   prisma.position.delete({ where: { id } })
5. 返回 { success: true }
```

## 六、潜在风险与应对措施

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| 存量数据迁移出错 | 职位默认模型绑定异常，评分计算失败 | 低 | 迁移脚本幂等设计；迁移后全量重算得分；迁移前备份 SQLite 文件 |
| `prisma db push` 导致数据丢失 | 不可接受 | 低 | push 前手动备份 `data/resume.db`；先 dry-run 检查变更 |
| 停用状态校验遗漏 | 停用职位仍可被修改 | 中 | 前后端双重校验；API 层统一校验 middleware 或 service 函数 |
| 删除级联误删 | 模型被意外删除 | 低 | 仅 DELETE /api/positions 执行级联；删除前简历数校验保证安全 |
| 旧路由 404 引发用户困惑 | 书签或缓存指向旧页面 | 低 | 告知用户导航变更（不保留重定向） |
| 评分计算性能 | 每次保存评分都全量重算 | 低 | `autoCalculateScores` 性能尚可（单次查询+简单计算），SQLite 瓶颈不在这里 |
| 并发切换默认模型 | 多个请求同时设定不同默认模型 | 极低 | SQLite 串行写入天然防护；应用层单实例无需额外处理 |
| PositionEditor 组件过于复杂 | 维护困难 | 中 | 拆分成 PositionEditor + WeightModelGroup + WeightModelCard 三层组件，各司其职 |
