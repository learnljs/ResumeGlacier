## 1. 功能规格

### 1.1 概述

在 Dashboard「收取趋势」图表和岗位维度趋势图表（`PositionTrendChart`）中，新增时间范围选择器，实现「统计粒度 × 时间长度」二维独立控制。

### 1.2 用户故事

| # | 作为 | 我想要 | 以便 |
|---|------|--------|------|
| US1 | HR | 在每日粒度下查看近一个月的趋势 | 看清日级波动在更长时间窗口中的变化 |
| US2 | HR | 查看系统运行以来的全部数据趋势 | 了解整体收取节奏，而不需要导出 Excel |
| US3 | HR | 在不同粒度间切换 | 快速找到合适的时间尺度，操作可预测 |

### 1.3 粒度 × 时间范围矩阵

| 粒度 | 近一周 (7天) | 近三周 (21天) | 近一个月 (30天) | 全部 (软上限 90天) |
|------|:---------:|:----------:|:-----------:|:--------------:|
| **每日** | ★ 默认 | — | — | — |

| 粒度 | 近 4 周 (4周) | 近 8 周 (8周) | 近 12 周 (12周) | 全部 (软上限 26周) |
|------|:----------:|:----------:|:------------:|:--------------:|
| **每周** | ★ 默认 | — | — | — |

| 粒度 | 近 3 个月 (3月) | 近 6 个月 (6月) | 近 12 个月 (12月) | 全部 (软上限 24月) |
|------|:------------:|:------------:|:-------------:|:--------------:|
| **每月** | ★ 默认 | — | — | — |

★ = 该粒度默认值。切换粒度时时间范围自动回到默认值。页面刷新也回到默认值。

### 1.4 交互行为

| 操作 | 行为 |
|------|------|
| 同一粒度下切换时间范围 | 立即发起 API 请求，刷新图表 |
| 切换粒度 | 时间范围自动跳回该粒度默认值（不跨粒度记忆） |
| 页面刷新 | 粒度回到「每日」，时间范围回到「近一周」 |
| 「全部」命中软上限 | 副标题显示截断说明，如「每日 · 全部（近 90 天）」 |

### 1.5 边界态

| 状态 | 条件 | UI 表现 |
|------|------|---------|
| 暂无数据 | 所选时间范围内 resume 数为 0 | 居中空状态插图 +「暂无数据」 |
| 数据点不足 | 数据点 < 2 个 | 保留折线图渲染（即使只有 1 个点），顶部黄色 banner：「数据点较少，建议切换更长时间范围」，附「查看默认范围」链接 |
| 参数非法 | granularity 或 range 不在合法枚举中 | API 返回 400 + 合法值列表 |

### 1.6 验收标准

- [ ] 图表右上角显示粒度按钮组（每日/每周/每月）+ 时间范围下拉（标签「时间：」）
- [ ] 每个粒度下可切换 4 种时间范围，默认值正确
- [ ] 切换粒度 → 时间范围自动回到默认
- [ ] 切换时间范围 → 图表刷新（有 loading 态）
- [ ] 选择「全部」命中软上限时，副标题显示截断说明
- [ ] 无数据时显示空状态占位
- [ ] 数据点 < 2 时显示黄色提示 banner
- [ ] 移动端宽度不足时，时间范围下拉折到第二行
- [ ] 折线图不再渲染柱状图
- [ ] 岗位趋势图表同样支持时间范围选择
- [ ] 页面刷新后回到默认组合

## 3. 数据库

### 3.1 表结构

**无 schema 变更。** 仅查询方式变更——从逐段 COUNT 改为 GROUP BY。

### 3.2 核心查询

时间基准字段：`COALESCE(sourceEmailReceivedAt, createdAt)`，标记为 `effectiveDate`。

```sql
-- 每日粒度（示例：近一个月，30 个 bucket）
SELECT
  date(COALESCE(sourceEmailReceivedAt, createdAt)) AS bucket,
  COUNT(*) AS count
FROM Resume
WHERE effectiveDate >= ? AND effectiveDate < ?
  [AND positionId = ?]  -- 仅岗位趋势
GROUP BY bucket
ORDER BY bucket ASC
```

```sql
-- 每周粒度（示例：近 12 周）
SELECT
  date(COALESCE(sourceEmailReceivedAt, createdAt), 'weekday 1', '-7 days') AS bucket,
  COUNT(*) AS count
FROM Resume
WHERE effectiveDate >= ? AND effectiveDate < ?
GROUP BY bucket
ORDER BY bucket ASC
```

```sql
-- 每月粒度（示例：近 6 个月）
SELECT
  strftime('%Y-%m', COALESCE(sourceEmailReceivedAt, createdAt)) AS bucket,
  COUNT(*) AS count
FROM Resume
WHERE effectiveDate >= ? AND effectiveDate < ?
GROUP BY bucket
ORDER BY bucket ASC
```

SQLite `date()` 不支持 `weekday` 修饰符的复杂计算——每周 GROUP BY 需要在应用层计算每个 bucket 的边界，走 `getDateRanges` 生成区间列表后按区间查询。详细实现见 `trend-service.ts`。

### 3.3 索引

已有索引不需要变更。`sourceEmailReceivedAt` 和 `createdAt` 字段的查询走全表扫描在 SQLite + 万级数据下可接受。如果未来数据量增长到十万级，考虑为 `COALESCE` 表达式建计算列索引（SQLite 3.31+ 支持 generated columns）。

## 4. API 设计

### 4.1 端点总览

| 方法 | 端点 | 说明 |
|------|------|------|
| GET | `/api/dashboard/stats` | 摘要数据（删除 trends 字段） |
| GET | `/api/dashboard/trends` | **新** 总趋势 |
| GET | `/api/dashboard/position-trends` | 岗位趋势（增强） |

### 4.2 GET /api/dashboard/trends

**Query 参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `granularity` | `'daily' \| 'weekly' \| 'monthly'` | 是 | 统计粒度 |
| `range` | `'week' \| '3weeks' \| 'month' \| 'all'` (daily) / `'4weeks' \| '8weeks' \| '12weeks' \| 'all'` (weekly) / `'3months' \| '6months' \| '12months' \| 'all'` (monthly) | 是 | 时间范围 |

**成功响应 200：**

```typescript
{
  granularity: 'daily',
  range: 'month',
  label: '每日 · 近一个月',         // 图表副标题
  truncated: false,                 // 软上限是否截断
  data: Array<{
    date: string,                   // ISO 日期字符串
    count: number,                  // 该 bucket 的简历数
    label: string                   // X 轴标签
  }>
}
```

**错误响应 400：**

```typescript
{
  error: '无效的统计粒度: hourly',
  validGranularities: ['daily', 'weekly', 'monthly']
}
```

### 4.3 GET /api/dashboard/position-trends

**变更：** `type` → `granularity` + `range`。

**Query 参数：**

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `positionId` | `string` | 是 | 岗位 ID |
| `granularity` | `'daily' \| 'weekly' \| 'monthly'` | 是 | 统计粒度 |
| `range` | 同上 | 是 | 时间范围 |

**响应结构** 与 `/api/dashboard/trends` 一致，额外增加 `positionName` 字段。

### 4.4 GET /api/dashboard/stats（变更）

**删除** `trends.daily`、`trends.weekly`、`trends.monthly` 字段。其余字段（`stats`、`positionStats`、`recentResumes`、`emailConfigs`、`resumeSources`）不变。

**不再使用的代码：** 删除 `getPast7Days`、`receivedAtWhere` 辅助函数以及所有趋势相关的 Prisma 查询逻辑。

### 5.2 共享组件接口

```typescript
// types/trend.ts
type TrendGranularity = 'daily' | 'weekly' | 'monthly';

type TimeRange =
  // daily
  | 'week' | '3weeks' | 'month' | 'all'
  // weekly
  | '4weeks' | '8weeks' | '12weeks'
  // monthly
  | '3months' | '6months' | '12months';

interface TrendDataPoint {
  date: string;
  count: number;
  label: string;
}

interface TrendResponse {
  granularity: TrendGranularity;
  range: TimeRange;
  label: string;
  truncated: boolean;
  data: TrendDataPoint[];
}

// 每个粒度对应的可用时间范围
const TIME_RANGE_OPTIONS: Record<TrendGranularity, TimeRange[]> = {
  daily:   ['week', '3weeks', 'month', 'all'],
  weekly:  ['4weeks', '8weeks', '12weeks', 'all'],
  monthly: ['3months', '6months', '12months', 'all'],
};

// 每个粒度的默认时间范围
const DEFAULT_TIME_RANGE: Record<TrendGranularity, TimeRange> = {
  daily: 'week',
  weekly: '4weeks',
  monthly: '3months',
};
```

### 5.3 状态管理

Dashboard 页面使用 React `useState`（无外部状态库）：

```typescript
const [granularity, setGranularity] = useState<TrendGranularity>('daily');
const [timeRange, setTimeRange] = useState<TimeRange>('week');
const [trendData, setTrendData] = useState<TrendResponse | null>(null);
const [trendLoading, setTrendLoading] = useState(false);
```

切换粒度时联动重置 timeRange：

```typescript
const handleGranularityChange = (g: TrendGranularity) => {
  setGranularity(g);
  setTimeRange(DEFAULT_TIME_RANGE[g]);  // 联动重置
};
```

趋势数据获取通过 `useEffect` 依赖 `[granularity, timeRange]` 自动触发。

### 5.4 X 轴标签自适应

```typescript
function getXAxisInterval(dataLength: number): number {
  if (dataLength <= 14) return 0;       // 全部显示
  if (dataLength <= 30) return 4;       // 每 5 个显示 1 个
  if (dataLength <= 60) return 6;       // 每 7 个显示 1 个
  return Math.ceil(dataLength / 12);    // 约每月 1 个标签
}

// 每日粒度超过 14 个点时取消星期后缀
function formatDailyLabel(date: Date, dataLength: number): string {
  const base = `${date.getMonth() + 1}月${date.getDate()}日`;
  if (dataLength <= 14) {
    const weekdays = ['周日', '周一', '周二', '周三', '周四', '周五', '周六'];
    return `${base} ${weekdays[date.getDay()]}`;
  }
  return base;
}
```

## 6. 后端服务设计

### 6.1 trend-service.ts

```typescript
// lib/services/trend-service.ts

interface DateRange {
  start: Date;
  end: Date;
  label: string;
}

interface TrendQueryParams {
  granularity: TrendGranularity;
  range: TimeRange;
  positionId?: string;
}

interface TrendResult {
  granularity: TrendGranularity;
  range: TimeRange;
  label: string;
  truncated: boolean;
  data: TrendDataPoint[];
}

/**
 * 根据粒度和时间范围生成要查询的日期区间列表。
 * 软上限在此处生效。
 */
function getDateRanges(granularity: TrendGranularity, range: TimeRange): {
  ranges: DateRange[];
  truncated: boolean;
}

/**
 * 对日期区间列表执行 GROUP BY 查询，返回每个 bucket 的 count。
 */
async function queryTrendCounts(
  ranges: DateRange[],
  granularity: TrendGranularity,
  positionId?: string
): Promise<Array<{ label: string; count: number }>>
```
